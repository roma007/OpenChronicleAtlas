# 京杭大运河主体归属规则（横向类与双挂载）

- **日期**：2026-11-23（M292 更正 M291 的错误结论）
- **关联**：`docs/research/units/grand-canal-people.md`、`docs/conversations/2026-11-23-运河城镇主体归属M291.md`
- **结论**：城镇/市场是**横向类**，节点同时挂「所属朝代层 + 沿线城镇与市场层」；
  双挂载是正常机制，不是缺陷。

## 1. 先纠正一个错误结论

M291 曾把「各层事件数相加超过事件总数（54 > 48）」当作缺陷，据此把城镇节点改成只挂城镇层。
这个理由不成立：

- 其他专题本来就有大量双挂载：抗日战争 94 条、长征 38 条；
- 长征里 `红三军团 + 红十五军团`、抗战里 `日本 + 中国守军`，都是**同一件事属于两层**；
- 双挂载时各层计数相加必然大于事件总数，这是定义问题，不是数据错误。

## 2. 七个主体的两套轴

`grand-canal` 的七个主体不是同一种分类：

| 轴 | 主体 |
| --- | --- |
| 纵向（时段／体系） | 隋唐大运河、北宋汴河漕运、南宋江南运河、元代运河工程、元明清漕运 |
| 横向（跨时段的类） | 沿线城镇与市场、黄河改道与运河衰落 |

横向类按定义跨越朝代：湖墅在南宋、德州仓在明、扬州盐运在清。
如果横向类只能单挂，就会出两个问题：

1. **时段视图残缺**：只看「北宋汴河漕运」，开封从图上消失——一个没有开封的北宋汴河；
2. **事件被迫复制或降级**：复制一份会破坏「一个事件一条记录」，改用 `relatedIds` 则标记不会出现在时段图层里。

所以横向类的节点必须双挂：`entityIds` 第一项是所属时段层（决定标记主色），第二项是横向类层。

## 3. 双挂载 ≠ 不分主体

双挂载不是随便加，先过「行为主体」这一关（与 `docs/research/units/anti-japanese-war-entity-audit.md` 同一套）：

| 判据 | 归入 |
| --- | --- |
| 朝廷、漕运总督、河道总督、工部的行动 | 对应时段层 |
| 地方官府、仓场、钞关、商人、市场 | 时段层 + 沿线城镇与市场 |
| 黄河、近代交通、制度废止 | 黄河改道与运河衰落 |

反例（不该双挂）：

- 「汴河岁运六百万石」是朝廷定的岁额，只挂北宋汴河漕运，不进城镇层；
- 「宋礼、白英治会通河」是朝廷工程，只挂元明清漕运，不进城镇层；
- 两条不同的行动不因为发生在同一城、同一河就合并挂载。

## 7. 边界情形

- **济宁会通河枢纽（1300）** 是航道系统节点（会通河与泗水交汇），只挂元明清漕运；
  济宁的市镇商业另见「济宁州城与运河商业（1450）」。
- **杭州南宋漕运（1200）** 写的是行在依赖江南运河的漕运，不是市镇，只挂南宋江南运河。
- 判断顺序：先定行为主体，再定是否属横向类；不按地点、不按热闹程度挂。
