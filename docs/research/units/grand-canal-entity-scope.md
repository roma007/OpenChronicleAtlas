# 京杭大运河主体归属规则（城镇节点为何单列）

- **日期**：2026-11-23
- **关联**：M291、`docs/research/units/grand-canal-people.md`
- **结论**：一个事件只挂一个主体；城镇节点归「沿线城镇与市场」，朝代层用 `relatedIds` 关联。

## 1. 判据：看行动主体，不看地点

| 行动主体 | 归入 |
| --- | --- |
| 朝廷、漕运总督、河道总督、工部 | 隋唐大运河 / 北宋汴河漕运 / 元代运河工程 / 元明清漕运 |
| 地方官府、仓场大使、钞关、商人、船户、市场 | 沿线城镇与市场 |
| 黄河、近代交通、制度废止 | 黄河改道与运河衰落 |

同一地点可以出现在不同层，但要看**这条事件写的是谁在做什么**：

- 「汴河岁运六百万石」——朝廷定的岁额，归北宋汴河漕运。
- 「开封汴河市镇」——汴河带来的码头、邸店与市场，归沿线城镇与市场。

## 2. 为什么不做双重挂载

早期做法是让城镇事件同时挂朝代层与城镇层，理由是「两个读法都成立」。代价有三：

1. **层计数虚高**：48 个事件，各层相加却是 54。
2. **层语义被稀释**：只看「北宋汴河漕运」时，会看到城镇商业内容，与层名不符。
3. **筛选重复**：同时开两层，同一标记出现两次；关掉城镇层，朝代层里又冒出来。

因此改为**单主体**：城镇节点只在城镇层；朝代层用 `relatedIds` 指回相关事件
（如开封市镇 → `song-canal-960`，德州仓 → `ming-canal-1415`），点击仍可跳转。

## 5. 边界情形

- **济宁会通河枢纽（1300）** 仍留「元明清漕运」：写的是会通河与泗水交汇形成的**漕运枢纽**，
  属航道系统节点；济宁的市镇商业另见「济宁州城与运河商业（1450）」。
- **杭州南宋漕运（1200）** 仍留「南宋江南运河」：写的是行在依赖江南运河的漕运，不是市镇。
- 若某事件确实同时属于两类（如「淮安漕运总督驻清江浦」），按**主要行动主体**归类，
  另一层用 `relatedIds` 关联，不在两层重复计数。
