# 2026-11-23 运河城镇节点不再挂进朝代层（M291）

- **日期**：2026-11-23
- **参与者**：用户（项目负责人）、AI 开发助手
- **关联版本**：v1.0.273
- **关联文档**：[主体归属规则](../research/units/grand-canal-entity-scope.md)、[CHANGELOG](../changelog/CHANGELOG.md)

> **本轮的结论已被 M292 推翻（保留作为纠错记录）。**
> 「各层相加超过事件总数」不是缺陷：双挂载本来就是其他专题的常规做法（抗战 94 条、长征 38 条）。
> 城镇是横向类，节点应当同时挂朝代层与城镇层。M292 已恢复双挂载，并补上 M291 漏挂的湖墅、济宁两条。

## 1. 用户的问题

「开封汴河市镇为什么要放北宋汴河漕运主体？」

这是上一轮解释留下的矛盾：一边说城镇节点单列成层，一边又让它同时挂在朝代层，
理由是「两个读法都成立」。用户看到的正是这种双重身份。

## 2. 为什么会这样

M287 拆主体时用的是**双重挂载**：

- 事件写一次，`entityIds` 同时含朝代层与城镇层；
- 好处是选朝代层也能看到城镇；
- 代价是层的语义被稀释，且各层事件数相加超过总数。

M289 之后暴露得更明显：48 个事件，七个主体相加是 54。

## 3. 改法

**一个事件只挂一个主体，按行动主体归类：**

| 事件 | 改后主体 | 类别 |
| --- | --- | --- |
| 开封汴河市镇 | 沿线城镇与市场 | 经济 |
| 德州仓与南运河转运 | 沿线城镇与市场 | 漕运 |
| 临清钞关 | 沿线城镇与市场 | 经济 |
| 通州仓与漕粮入京 | 沿线城镇与市场 | 漕运 |
| 苏州丝米市 | 沿线城镇与市场 | 贸易 |
| 扬州盐运 | 沿线城镇与市场 | 贸易 |
| 临安湖墅市镇 | 沿线城镇与市场 | 贸易 |
| 济宁州城与运河商业 | 沿线城镇与市场 | 贸易 |

朝代层通过 `relatedIds` 指回这些节点（如开封 → `song-canal-960`、德州仓 → `ming-canal-1415`），
点击仍能跳转，不再重复计数。

## 4. 顺带修掉的问题

6 个城镇事件原先用的是 M75 示例留下的占位来源（《隋书·炀帝纪》《元史·河渠志》等），
与「明代德州设仓」「清代苏州米市」无关。本批换成对应史料：

- 开封：《东京梦华录》卷一《河道》、《宋史·河渠志》、《清明上河图》、《中国运河志》；
- 德州仓、通州仓：《明史·食货志》《明会典》《漕运通志》与地方志；
- 临清钞关：《明史·食货志》《明会典》《临清州志》；
- 苏州：《清史稿·食货志》《苏州府志》《吴县志》；
- 扬州：《清史稿·食货志》（盐法）《两淮盐法志》《扬州府志》。

日期仍是代表年（1100、1450、1750），正文注明；无法核实的仓名、税额写「待考」。
