## 跨项目回执

### 1. TLS 切换请求（`2026-11-23-atlas-to-quizgo-enable-443-tls.md`）→ done

QuizGo 按我方案执行，采纳了全部要点：证书挂载、`00-default.conf` 未知 Host 兜底、
`server_name` 带 www、`qz_auth`/`qz_api` 限流、`/v1/admin/` 整体收口、HSTS 延后、只 recreate `web`。

**唯一被否决的是「管理后台收进 tailnet」**：用户明确要求任何设备都能登录后台，
于是改为三层防护（≥12 位口令、`qz_auth` 10r/m、Go 侧 5 次/15 分钟），并保留「一行收回 tailnet」的回滚。

我原写的一条验收期望因此要修正：`/v1/admin/auth/login` 期望值是 **401**（流量进得来、应用层在工作），
不是 403；期望 403 的只剩 `/metrics`。这条我在回复里确认了，避免以后按错标准判故障。

它还报了一个真实踩过的坑：`/srv/nginx/nginx.conf` 是**单文件 bind 挂载**，
`rsync` 默认「写临时文件 + rename」换 inode，容器仍读旧文件，出现「conf.d 已更新、nginx.conf 未更新」
的半更新状态（首发报 `zero size shared memory zone "qz_auth"`，`deploy.sh` 自动回滚）。
它改成 `--inplace` + 同步后断言 md5。**Atlas 侧的 `pnpm release` 只 rsync `apps/web/dist` → `/srv/atlas`，
不碰 `/srv/nginx`，所以不受影响**，无需跟改。

## 判断记录

- **为什么不把 `pnpm release` 的自检改成 `curl -k` 或走 8081 兜底**：正式入口的证书链本身就是要验的东西之一
  （手机端不报错的关键）。用 `-k` 等于把最该验的一项关掉。
- **为什么证书续期不交给 QuizGo**：证书在阿里云账号下，申请要登录控制台与点击授权，
  这些是账号级动作；QuizGo 只碰「reload」这种容器级动作，边界清楚。
- **为什么不在 `status.sh` 用 `⚠️` 标证书临期**：`deploy.sh` 把 `⚠️` 当漂移硬拦，
  而证书临期时恰恰必须能发布（发布正是为了修它）。用 `⏳` / `❌`。
