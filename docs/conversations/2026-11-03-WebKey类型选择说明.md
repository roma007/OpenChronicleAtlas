## 1. 原始需求

用户提问：

> 为什么 web 的不是选「Web 服务」？

背景：高德控制台「服务平台」有 Android、iOS、Web 端 (JS API)、Web 服务等多个选项，用户不确定 Web 端应该申请哪一种。

## 3. 讨论与决策

| 编号 | 议题 | 结论 | 依据 |
| --- | --- | --- | --- |
| D1 | 浏览器内交互地图用哪种 Key | **Web 端 (JS API)** | JS API 才能渲染地图、Marker、Polyline |
| D2 | Web 服务 Key 的用途 | 服务端 REST：地理编码、POI 搜索、路径规划、静态地图、坐标转换 | 官方服务划分 |
| D3 | 两者是否互斥 | **不互斥，互补**；可同时申请 | 鉴权方式与调用位置不同 |
| D4 | 本项目当前是否申请 Web 服务 Key | **暂不申请**。M1 无服务端；M3 若做服务端搜索代理再申请 | 减少不必要的 Key 与配额管理 |
| D5 | Web 服务 Key 能否放前端 | **绝对不能**。应放服务端环境变量 + IP 白名单 | 前端可见即泄露 |

## 4. 疑问与答复

| 编号 | 疑问 | 答复 | 状态 |
| --- | --- | --- | --- |
| Q1 | 用 Web 服务 Key 能不能显示地图？ | 不能。它只返回 JSON/图片，不提供浏览器地图渲染能力 | 已确认 |
| Q2 | 为什么 Web 端必须配安全密钥？ | JS API Key 必然暴露在前端，高德用「域名白名单 + `securityJsCode`」限制滥用；Web 服务 Key 用 IP 白名单，不适用于浏览器 | 已确认 |
| Q3 | 以后搜索功能需要 Web 服务 Key 吗？ | 若搜索由前端 JS API 插件完成，不需要；若走后端 REST（推荐用于跨专题检索/缓存），则需要 | 待 M3 设计确认 |
| Q4 | 两个 Key 的配额是否共用？ | 不共用，按 Key/服务分别计算 | 已确认 |
