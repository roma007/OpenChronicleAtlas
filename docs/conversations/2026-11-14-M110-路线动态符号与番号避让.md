## 1. 原始需求

M109 完成后，AI 说明剩余方向：

> 路线几何仍是示意折线，没有沿公路、河谷、山口补点；番号牌没有碰撞避让；进攻/追击线还没有流动箭头或播放时的线头光点。

用户回复：

> 继续

本轮按「先做动态符号与番号避让、几何补点留到下一轮」推进，避免在未核对史料的情况下改动路线坐标。

## 2. 需求拆解

| 编号 | 需求点 | 类型 | 优先级 |
| --- | --- | --- | --- |
| R1 | 播放时能看出路线推进到哪里 | UI | 高 |
| R2 | 箭头方向与路线走向一致 | UI | 高 |
| R3 | 防御线不显示推进箭头 | UI | 高 |
| R4 | 密集区番号牌不互相压盖 | UI | 高 |
| R5 | 番号牌不被事件计数气泡盖住 | UI | 中 |
| R6 | 图例解释新符号 | UI | 中 |
| R7 | 不修改历史数据 | 约束 | 高 |

## 3. 讨论与决策

| 编号 | 议题 | 结论 | 依据 |
| --- | --- | --- | --- |
| D1 | 先做几何补点还是动态符号 | 先做动态符号与番号避让 | 几何补点需逐条核对史料，风险与工作量都更大 |
| D2 | 线头用 Polyline 还是 Marker | Marker + CSS 三角 | 高德 Polyline 不支持 dash offset，Marker 可固定像素 |
| D3 | 哪些路线显示线头 | 所有非防御路线 | 红军主线同样需要方向提示 |
| D4 | 线头何时隐藏 | 缩放 < 5、进度 < 1%、进度 > 99.9% | 避免总览杂乱、与起点据点重叠 |
| D5 | 标签尺寸怎么测 | 文本估算，不读 DOM | 30fps 下读 DOM 会强制布局 |
| D6 | 标签与聚合圆点冲突 | 提高标签 zIndex，不做避让 | 避让会导致密集区番号大面积消失 |
| D7 | 标签避让优先级 | 防御线优先，其余按 order | 防御线番号承载封锁线归属，信息更关键 |

## 4. 实现要点

### 4.1 线头箭头

- `sampleRoute` 增加 `bearing`（0 = 正北，顺时针）；
- 非防御路线创建一个 `.atlas-route-head` Marker；
- 时间轴 effect 中按 `progress` 取点，设置 `rotate(bearing)` 并显隐；
- 缩放 ≥ 5、进度 1%–99.9% 才显示。

### 4.2 番号牌避让

- 候选：缩放 ≥ 6、进度 ≥ 45%；
- 估算外接框：汉字 11 px、西文 6.2 px、高 18 px、左右 padding 14 px；
- 按「防御线优先 + order」排序，贪心放置，重叠 3 px 即隐藏；
- 番号牌 `zIndex` 120，高于事件聚合圆点。
