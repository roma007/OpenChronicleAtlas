## 1. 原始需求

用户：

> 继续按计划实施功能开发把

结合原始需求与 M5 收尾审计，本轮继续实现尚未完成的核心体验功能：

- 原始需求 §6.2：「节点 Marker/聚合」；
- 原始需求 §6.3：「支持时间轴缩放与跳转到指定日期」；
- 审计遗留 A7：「无 Marker 聚合/离线，M5 后迭代」。

## 2. 本轮范围

| 编号 | 功能 | Web | 移动端 |
| --- | --- | --- | --- |
| F1 | 事件 Marker 按缩放级别聚合 | ✅ | ✅ |
| F2 | 聚合点显示事件数量，点击放大 | ✅ | ✅ |
| F3 | 时间轴缩放（0—8 级） | ✅ | ✅ |
| F4 | 缩放后刻度、拖动、日期跳转自适应 | ✅ | ✅ |
| F5 | 共享聚合算法与单测 | ✅ | 共用 |

不在本轮范围：离线缓存、i18n、iOS 真机、商店提审、自定义域名。

## 3. 关键决策

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| D1 | 聚合算法放在 `packages/shared` | Web / 移动端共用，避免两套逻辑 |
| D2 | 采用「随缩放级别变化的经纬网格」聚合 | 不依赖各端地图投影 API，三端行为一致、可单测 |
| D3 | 聚合只改变 Marker，不改变路线与时间轴数据 | 降低风险，保持事件-路线抽查结果 |
| D4 | 时间轴缩放采用「视口窗口」而非压缩整条时间轴 | 刻度与拖动逻辑改动最小，日期跳转仍用绝对时间 |
| D5 | 缩放级别 0—8，最小视口 1 天 | 覆盖两年跨度到单日精度 |
| D6 | 聚合点在缩放后重建，时间变化只更新数量/可见性 | 避免播放时反复创建 DOM / 原生 Marker |
