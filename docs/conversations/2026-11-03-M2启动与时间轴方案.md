## 1. 原始需求

M1 完成后，助手询问是否开始 M2 方案，用户答复：

> 继续

即：按里程碑顺序进入 M2 —— **通用时间轴（拖动/播放/刻度自适应）+ 路线动画 + 节点高亮（Web）**。

## 2. 需求拆解

| 编号 | 需求点 | 类型 | 优先级 |
| --- | --- | --- | --- |
| R1 | 时间范围由 manifest 动态生成，刻度自适应（年/月/日） | 功能 | P0 |
| R2 | 拖动、播放/暂停、倍速 0.5/1/2/4x | 功能 | P0 |
| R3 | 拖动时只显示该时间点之前的路线与节点 | 功能 | P0 |
| R4 | 路线沿线生长动画 | 功能 | P0 |
| R5 | 当前事件高亮 + 事件气泡 | 功能 | P0 |
| R6 | 时间轴缩放与跳转到指定日期 | 功能 | P1 |
| R7 | 键盘可操作、对比度达标 | 无障碍 | P0 |
| R8 | 时间轴计算抽到 shared，供移动端复用 | 架构 | P0 |
| R9 | 单测覆盖时间/刻度/路径插值 | 测试 | P0 |
| R10 | 文档先行并双仓留档 | 文档 | P0 |

## 3. 讨论与决策

| 编号 | 议题 | 结论 | 依据 |
| --- | --- | --- | --- |
| D1 | 时间粒度 | 沿用 **UTC 日粒度**，与 M1 数据契约一致 | schema v1.0.0 |
| D2 | 刻度算法 | 根据时间跨度与可用宽度选择 年/月/日，目标 4–12 个主刻度 | design §4.2 |
| D3 | 路线动画实现 | 时间驱动 + 预计算累计长度 + `Polyline.setPath(partialPath)` | ADR-0005 |
| D4 | 播放帧率 | `requestAnimationFrame`，地图更新节流到 ~30fps | 性能 |
| D5 | 全程播放时长 | 1x 下 60 秒走完整个专题；倍速按比例缩短 | design §4.4 |
| D6 | 当前事件 | 时间点之前最近的事件；持续事件在区间内保持高亮 | design §4.5 |
| D7 | 事件气泡 | 使用高德 `InfoWindow`，播放跨过事件时自动打开，4 秒后关闭 | design §6.3 |
| D8 | 时间轴位置 | Web 底部固定面板；移动端 M4 改为抽屉 | 需求 §九 |
| D9 | 状态管理 | Zustand 增加 timeline slice，时间计算仍放 shared | 架构一致性 |
| D10 | 文档先行 | 先提交 M2 plan/design/ADR，确认后再编码 | 铁律 |

## 4. 疑问与答复

| 编号 | 疑问 | 答复 | 状态 |
| --- | --- | --- | --- |
| Q1 | 播放时用户拖动时间轴如何处理？ | 拖动即暂停播放，松开后保持暂停，需手动继续 | 已确认 |
| Q2 | 路线分段之间有间隔时如何动画？ | 各段独立按各自 `startDate/endDate` 生长，不跨段插值 | 已确认 |
| Q3 | 事件气泡与详情面板冲突？ | 气泡仅展示名称/日期，点击后打开详情面板并暂停 | 已确认 |
| Q4 | 是否需要时间轴缩放（zoom）？ | M2 先支持「跳转到日期 + 刻度自适应」；独立缩放控件延后 | 待确认 |
| Q5 | 移动端是否同步实现？ | M2 只做 Web，移动端 M4 复用 shared 时间轴 | 已确认 |
| Q6 | 数据是否需要扩充？ | M2 沿用 M1 的 28 事件 / 9 段路线，先验证交互 | 已确认 |
