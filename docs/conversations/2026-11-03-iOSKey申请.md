## 1. 原始需求

用户贴出高德控制台 **iOS 平台**的 Key 申请页，表单包含：

> Key 名称 / 服务平台（Android、iOS、Web端 JS API、Web服务…）/ 可使用服务（iOS 地图 SDK、定位 SDK、导航 SDK…）
> 安全码 Bundle ID
> 服务协议、隐私政策与 SDK 合规说明。

用户需要：**这份 iOS Key 表单怎么填**，以及与项目配置的对应关系。

## 3. 讨论与决策

| 编号 | 议题 | 结论 | 依据 |
| --- | --- | --- | --- |
| D1 | Key 名称 | `atlas-ios` | 与 `atlas-android` / `atlas-web` 命名一致 |
| D2 | 服务平台 | **iOS 平台** | 表单要求 |
| D3 | 可使用服务 | 先勾 **iOS 地图 SDK**；定位 SDK 延后 | M1/M4 不需要定位；减少权限与合规面 |
| D4 | 安全码 Bundle ID | **`com.openchronicle.atlas`** | 与 ADR-0004 约定的三端统一标识一致 |
| D5 | 是否需要 SHA1 | **不需要**，iOS 只绑定 Bundle ID | 高德 iOS Key 机制 |
| D6 | Bundle ID 注册 | 需在 Apple Developer 后台注册；EAS Build 可自动注册 | 上架与真机签名要求 |
| D7 | 扩展的 Bundle ID | Share Extension / Widget 使用独立 ID，主 Key 不覆盖 | 避免后续返工 |
| D8 | 注入方式 | `EXPO_PUBLIC_AMAP_IOS_KEY` + `expo-gaode-map` Config Plugin | 指南 §7.2 |
| D9 | 文档先行 | 先更新指南与对话档案，再继续后续配置 | 铁律 |

## 4. 疑问与答复

| 编号 | 疑问 | 答复 | 状态 |
| --- | --- | --- | --- |
| Q1 | Bundle ID 能否用 `com.openchronicle.atlas`？ | 可以，技术上不要求拥有 `openchronicle.com` 域名；但需在 Apple Developer 账号内唯一且注册。若已被他人占用，需换前缀（如 `com.roma007.openchronicleatlas`） | 待用户在 Apple 后台确认 |
| Q2 | iOS Key 能否给 Android 用？ | 不能，三端 Key 独立 | 已确认 |
| Q3 | 是否现在需要 iOS 定位 SDK？ | 不需要。M1 无定位；M4 若加「我的位置」再勾选并补隐私说明 | 已确认 |
| Q4 | 上架时 Bundle ID 与 Key 不一致会怎样？ | 地图鉴权失败（空白/报错），必须完全一致 | 已确认 |
