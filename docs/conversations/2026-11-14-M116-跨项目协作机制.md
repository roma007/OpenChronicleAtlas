## 1. 原始需求（用户原话摘要 / 引用）

> 「有没有建立两个项目更新服务器中共用的东西或者相互影响的东西时两个AI之间的沟通机制？
> 不可能靠我再继续这样传话。」

## 2. 需求拆解

| 编号 | 需求点 | 类型 | 优先级 |
| --- | --- | --- | --- |
| R1 | 两个 AI 之间要有固定通道，不再由用户转述 | 流程 | P0 |
| R2 | 共享资源要有归属，避免双写 | 流程 | P0 |
| R3 | 状态要可验证，能发现「有人没走流程」 | 机制 | P0 |
| R4 | 发布登记要自动化，不能靠记性 | 机制 | P1 |
| R5 | 并发改动共享 nginx 要能互斥 | 机制 | P1 |

## 3. 讨论与决策

| 编号 | 议题 | 结论 | 依据 |
| --- | --- | --- | --- |
| D1 | 通道放哪里 | 放服务器 `/srv/ops/`，不放任一方仓库 | 两个仓库互相独立且各自有 AGENTS.md；服务器是双方唯一的共同落点，读到的也是真实状态 |
| D2 | 是否需要第三个 git 仓库 | 不需要 | 契约只有一份，放仓库会产生副本漂移；放服务器单份即可，必要时再镜像 |
| D3 | 冲突怎么防 | 分文件所有权 + `flock` | `state/` 各写各的；`/srv/nginx` 改动前拿 `locks/nginx.lock`；journal 只追加 |
| D4 | 怎么发现静默漂移 | `state/` 登记 md5，`status.sh` 比对真实值 | 单向哈希比对，无需读对方仓库 |
| D5 | 请求怎么投递 | `requests/*.md`，front-matter + `## 回复` | 纯文本、可 diff、双方都能追加，不需要数据库与鉴权 |
| D6 | 是否需要自动化 hook | 暂不做 | 先让规则可读可用；等两边都接入后再考虑 pre-commit 检查 |

## 4. 机制结构

```
/srv/ops/
├── CONTRACT.md          归属表 + 动共享面四步 + 写入规则 + 红线
├── bin/status.sh        公共状态快照（只读）
├── state/
│   ├── atlas.json       Atlas 写
│   └── quizgo.json      QuizGo 写
├── journal/2026-11.log  只追加
├── requests/            跨项目请求（README 说明格式）
└── locks/               flock 目标
```

`status.sh` 输出：时间 / 双方版本 / 容器 / 监听端口 / nginx 三文件 md5 / 镜像一致性 /
**漂移检测** / 待处理请求 / 磁盘内存。
