# 对话档案：端点史实核查

- **日期**：2026-11-16
- **参与者**：用户（项目负责人）、AI 开发助手（DeepSeek V4.1 Flash / OpenCode）
- **关联**：[计划](../plans/2026-11-16-端点史实核查-plan.md)、[方案](../plans/2026-11-16-端点史实核查-design.md)

## 1. 原始需求

用户：

> 你这些方法跟硬接没什么差别，必须查到历史事实记录，把线头的前置事实、线尾的后续事实找出来。重新计划

## 2. 上一版错在哪

上一版把「补连接线 / 补事件 / 写 allowlist」当成处理手段，核心仍是「让检查通过」，几何上把两条线接起来，与硬接没有本质区别。

## 3. 新原则

> 先查到史实记录，再决定画不画、怎么画。

- 线头：查这支部队此前在哪里、何时、经哪条路线到这里；
- 线尾：查这支部队此后去了哪里、何时、经哪条路线离开；
- 每条结论必须有可核对出处；
- 查不到就写「已查，未得」并列出查过的来源，不画线、不拿「示意」掩盖。

## 4. 计划要点

- **台账**：`docs/research/route-endpoints/<atlas>.md`，每个端点一行：研究问题、史实结论、出处、处理；
- **处理只有四种**：补前置/后续路线段、补前置/后续事件、改坐标/拆段、有据的独立端点（附来源）；
- **分批按历史簇**：三国 → 隋唐 → 宋元 → 明清 → 抗日（日军进攻线 / 中国军队 / 盟军与华南）→ 全量复核；
- **验收**：62 条都有结论与出处或「已查未得」，`check:heads --all` 归零只是副产物。

## 5. 第一批

C1 三国 6 个端点：襄阳—当阳、官渡、高平陵、孙策渡江、吕蒙袭荆州、石亭。先做试点，验证台账格式与研究流程。
