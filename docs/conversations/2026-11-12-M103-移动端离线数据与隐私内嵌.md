## 1. 原始需求

在讨论 iOS 上架时，用户指出：

> 这个 `*.vercel.app` 必须要代理才能访问，不合适。那 APP 能不能先做本地数据库，然后以后建了服务器再升级呢？

随后确认继续实施，并要求把 SVG 封面一并处理、升级版本并提交。

## 2. 需求拆解

| 编号 | 需求点 | 优先级 |
| --- | --- | --- |
| R1 | 专题数据不依赖境外域名，App 可离线浏览 | P0 |
| R2 | 以后服务器就绪可平滑切换，不重构数据格式 | P0 |
| R3 | 隐私政策在 App 内可读，不依赖外部链接 | P1 |
| R4 | SVG 封面在移动端正常显示 | P1 |
| R5 | 按版本铁律升级并提交 | P1 |

## 3. 方案与决策

| 编号 | 议题 | 结论 |
| --- | --- | --- |
| D1 | 「本地数据库」实现方式 | 不引入 SQLite；5MB 只读静态数据使用构建期内置 JSON 更简单，沿用现有 loader/schema 校验 |
| D2 | 数据打包方式 | `scripts/build-mobile-data.ts` 生成静态 require 映射，Metro 直接打包 `data/atlases`，不复制数据副本 |
| D3 | GeoJSON | 自定义 Metro transformer，把 `.geojson` 转为 CommonJS 后交给 Expo babel transformer |
| D4 | 远端升级路径 | `EXPO_PUBLIC_DATA_BASE_URL` 有值时远端优先，失败回退内置；默认使用内置 |
| D5 | 隐私政策 | 复用 `@atlas/shared` i18n 文案，新增 App 内离线弹窗；ASC 元数据仍填公网 URL 供审核访问 |
| D6 | SVG 封面 | 用 sharp 转 1600×900 PNG，更新 `index.json` 与 manifest 的 cover 路径 |

## 4. 实施结果

- 新增 `apps/mobile/src/data/bundled.ts`、`apps/mobile/src/generated/atlasData.ts`、`apps/mobile/metro.transformer.js`。
- 新增 `apps/mobile/src/components/common/PrivacyPolicyModal.tsx`，首次启动与首页底部均可打开。
- `apps/mobile/src/data/client.ts` 统一数据源选择与图片解析。
- CI 在 Android/iOS prebuild 前执行 `pnpm build:mobile-data`。
- 6 张 SVG 封面转 PNG；`data/atlases` 体积约 5.5MB。

## 6. 遗留事项

- 地图瓦片仍由高德 SDK 联网加载，内置的是专题数据而非离线地图。
- App Store Connect 的隐私政策 URL 仍需公网地址（当前可用 Vercel，正式域名就绪后替换）。
- `*.vercel.app` 在中国大陆不可达；Web 正式发布仍建议绑定已备案域名。
