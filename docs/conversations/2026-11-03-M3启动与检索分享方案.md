## 3. 讨论与决策

| 编号 | 议题 | 结论 | 依据 |
| --- | --- | --- | --- |
| D1 | 全局搜索数据来源 | 读取 `data/atlases/index.json` 后按需加载各专题，内存建索引；专题数增长后再预生成索引 | ADR-0006 |
| D2 | 搜索范围 | 事件名、地名、摘要、描述、类型、实体名；跨专题可开关 | design §4 |
| D3 | 搜索匹配 | 归一化（小写、去空格）+ 子串匹配 + 简单评分；不做分词/拼音（M5 再评估） | design §4.2 |
| D4 | Markdown 渲染 | `react-markdown` + `remark-gfm` + `rehype-sanitize`，禁止原始 HTML | 安全 |
| D5 | 专题内筛选 | 实体沿用图例开关；新增类型多选 + 时间段；与时间轴叠加 | design §5 |
| D6 | 分享状态编码 | URL query：`?t=YYYY-MM-DD&event=<id>&view=lng,lat,zoom` | design §6 |
| D7 | 分享方式 | 优先 `navigator.share`，不支持则复制到剪贴板并提示 | Web 兼容 |
| D8 | 深链恢复 | 专题加载完成后只应用一次，避免覆盖用户后续操作 | design §6.3 |
| D9 | 搜索页位置 | 新增 `/search`，首页顶栏入口；结果点击跳到专题并选中事件 | design §5.4 |
| D10 | 文档先行 | 先提交 M3 plan/design/ADR，确认后编码 | 铁律 |

## 4. 疑问与答复

| 编号 | 疑问 | 答复 | 状态 |
| --- | --- | --- | --- |
| Q1 | 全局搜索是否默认跨专题？ | 默认跨专题；可在搜索页切换「仅当前专题」 | 已确认 |
| Q2 | 搜索是否支持拼音/模糊？ | M3 只做子串匹配；拼音与分词延后到 M5 | 已确认 |
| Q3 | 筛选的时间段与时间轴关系？ | 筛选是「额外约束」：事件必须同时满足筛选区间与当前时间轴位置 | 已确认 |
| Q4 | 分享链接是否需要短链/后端？ | M3 纯前端 query；短链与统计延后 | 已确认 |
| Q5 | 事件描述里的外链图片如何处理？ | `referrerPolicy="no-referrer"` + `loading="lazy"`；Markdown 图片同样限制 | 已确认 |
| Q6 | 移动端是否实现搜索/分享？ | M3 只做 Web；M4 复用 shared 搜索并接入系统分享 | 已确认 |

## 6. 实施结果（2026-11-03）

| 项 | 结果 |
| --- | --- |
| shared | 检索索引/查询、筛选、分享编解码；新增 18 个单测，shared 共 57 个测试通过 |
| 详情 | Markdown（sanitize）、图片、关联事件、来源、分享按钮；Markdown 按需加载 |
| 搜索 | `/search`：搜索「遵义」4 条结果，点击跳转并恢复时间/事件 |
| 筛选 | 类型多选 + 时间段；「重要会议」使 Marker 28 → 6，计数 6/28 |
| 分享 | 链接含 `t`/`event`/`view`；复制成功；深链恢复时间、事件与视野 |
| 移动端 | 390px 搜索、详情、筛选浮层均无横向溢出 |
| 检查 | typecheck / lint / test / build / validate:data 全部通过 |

**与方案的偏差**：

- Markdown 改为 `React.lazy` 按需加载，避免主包超过 500KB。
- Web Share 增加 1.5 秒超时降级复制；剪贴板失败用 `execCommand` 兜底。
- 深链带 `view` 时视野优先于事件定位。
- 搜索仍为子串匹配，未做拼音/分词（按 Q2 约定）。
