# M114 提交前自动升版与发布守则

- **日期**：2026-11-14
- **时间**：15:40
- **参与者**：用户（项目负责人）、AI 开发助手（OpenCode）
- **关联里程碑**：M114
- **关联文档**：`AGENTS.md` 第 1、7 节，`../OpenQuizGo/AGENTS.md` 第八节

## 1. 原始需求（用户原话摘要 / 引用）

> 「他项目的规约他自己执行，你项目的规约你自己建立和执行，不过他项目中每次提交都自动升级版本号这个规约挺好，你可以参考。」

前置背景：本次部署把 OpenChronicleAtlas 与 OpenQuizGo 放到同一台阿里云 ECS 上，发布守则原本只写在
`docs/deployment.md`，AI 不会自动读取；同时发现仓库根目录的文件名是小写 `agent.md`，OpenCode 查找的是
`AGENTS.md`，导致 5 条铁律从未被任何 AI 加载过。

## 2. 需求拆解

| 编号 | 需求点 | 类型 | 优先级 |
| --- | --- | --- | --- |
| R1 | 把提交即升版做成自动化，不依赖人记 | 约束 | P0 |
| R2 | 构建号与版本号必须可校验，防止漂移 | 约束 | P0 |
| R3 | 发布/回滚流程写进会自动加载的 `AGENTS.md` | 文档 | P0 |
| R4 | 修正 `agent.md` 大小写导致规则从未生效的问题 | 文档 | P0 |
| R5 | 清理历史文档里指向 `agent.md` 的失效引用 | 文档 | P2 |

## 3. 讨论与决策

| 编号 | 议题 | 结论 | 依据 |
| --- | --- | --- | --- |
| D1 | 规则写 `docs/` 还是 `AGENTS.md` | 红线与可执行命令写 `AGENTS.md`；推导与背景留在 `docs/`，并在 `AGENTS.md` 给出「场景 → 必读文件」映射 | OpenCode 只自动加载当前目录 `AGENTS.md` |
| D2 | 升版方式 | 仿 OpenQuizGo：pre-commit 钩子自动 `pnpm version:bump`，并 `git add` 版本文件 | 用户点名参考该做法 |
| D3 | 如何避免重复升版 | 比较 `HEAD:package.json` 与 `:package.json` 的版本，不同则视为已升版（兼容 amend 与手动指定版本） | 钩子幂等 |
| D4 | 构建号漂移 | `check:versions` 增加公式校验 `major*10000+minor*100+patch`；实测抓住「版本 1.0.3 + 构建号 10005」 | 本轮发现 `app.config.ts` / `tauri.conf.json` 构建号已到 10005 而版本仍是 1.0.3 |
| D5 | 版本文件有未暂存改动 | 钩子直接拒绝，避免 `version:bump` 覆盖正在编辑的内容 | 本轮 `app.config.ts` 同时含 WIP 插件改动 |
| D6 | M105–M113 那批未提交改动 | 先作为 `v1.0.5` 提交（构建号 10005 与该版本对应），钩子作为 `v1.0.6` 单独提交 | 用户选择「两笔提交」 |
| D7 | 是否自动打 tag | 不自动打：amend / rebase 会留下悬空 tag；改为在 `AGENTS.md` 给出命令，提交后手工执行 | 保守，避免错误 tag |
