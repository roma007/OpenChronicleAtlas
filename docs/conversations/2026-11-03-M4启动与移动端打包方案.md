## 1. 原始需求

M3 完成后，助手询问是否开始 M4 方案，用户答复：

> 要

即进入 M4：**共享层抽离 + Android APK + iOS IPA + 三端交互一致性验证**。

## 2. 需求拆解

| 编号 | 需求点 | 类型 | 优先级 |
| --- | --- | --- | --- |
| R1 | 移动端接入高德地图（expo-gaode-map）与共享数据/时间轴逻辑 | 功能 | P0 |
| R2 | Android 打包 APK/AAB，支持 Android 8.0+ | 交付 | P0 |
| R3 | iOS 打包 IPA，支持 iOS 14+ | 交付 | P0 |
| R4 | 三端交互一致：时间轴、路线、详情、筛选、搜索、分享 | 验收 | P0 |
| R5 | 数据读取同一套 `/data/atlases`，禁止各端副本 | 架构 | P0 |
| R6 | 高德 Key、签名、证书不入库；隐私合规 | 合规 | P0 |
| R7 | 移动端系统分享与深链 | 功能 | P1 |
| R8 | 文档先行、双仓同步、tag `v0.4.0-m4` | 文档 | P0 |

## 3. 讨论与决策

| 编号 | 议题 | 结论 | 依据 |
| --- | --- | --- | --- |
| D1 | 移动端地图库 | `expo-gaode-map`（Expo Modules + Config Plugin） | ADR-0004 / ADR-0007 |
| D2 | 导航 | React Navigation native-stack | ADR-0007 |
| D3 | 数据来源 | 远端 `/data/atlases` URL，与 Web 同一套数据；不打包副本 | 需求 §三 |
| D4 | 时间轴 | 复用 shared `timeline`，RN 用 PanResponder + rAF | 架构一致性 |
| D5 | 详情 | 底部抽屉 + Markdown（RN 渲染器） | 交互一致性 |
| D6 | 分享 | `Share.share` + deep link；M5 再做 universal link | 需求 §六 |
| D7 | Android 打包 | 本地 prebuild + Gradle（keystore 在仓库外）；EAS 作为备选 | 环境已具备 |
| D8 | iOS 打包 | 本地 Xcode + 签名；无 Apple 账号时先出模拟器包/未签名 archive | 环境已具备 Xcode 26.6 |
| D9 | 隐私 | 首次启动隐私同意后再初始化地图 SDK；不申请定位权限（M4 无定位） | 合规 |
| D10 | 文档先行 | 先提交 M4 plan/design/ADR-0007，确认后编码 | 铁律 |

## 4. 疑问与答复

| 编号 | 疑问 | 答复 | 状态 |
| --- | --- | --- | --- |
| Q1 | expo-gaode-map 是否兼容 Expo SDK 58 / RN 0.88 / 新架构？ | 需 T1 PoC 验证；不兼容则回退 `react-native-amap3d` 或自定义 Expo Module | 待 PoC |
| Q2 | 是否有 Apple Developer 账号与证书？ | 未知；没有则先交付模拟器构建 + 未签名 archive，IPA 待账号就绪 | 待确认 |
| Q3 | Android 发布 keystore 是否可用？ | 已生成 `~/.openchronicle/atlas-release.keystore`，需确认口令与备份 | 已具备 |
| Q4 | 移动端数据走远端还是内置？ | M4 走远端同一套数据；离线需求 M5 再评估打包 | 已确认 |
| Q5 | 是否需要定位/「我的位置」？ | M4 不做，避免权限与隐私面扩大 | 已确认 |
| Q6 | 三端一致性验收设备？ | Android 模拟器 API 26/34 + iOS 26 模拟器；真机由用户补测 | 待确认 |
