## 1. 原始需求

用户提供项目初始需求文件：`项目初始需求.txt`（189 行），要求按其「〇、铁律」执行启动动作。核心内容摘要：

> 开发跨三端（Web / Android / iOS）的通用历史事件时空地图平台，以「地图 + 时间轴」为核心交互；
> 专题（长征、抗战、丝绸之路、大航海等）以可插拔数据包接入，平台不硬编码任何专题内容。
> 使用双远程仓库（GitHub + Gitee）同步；每轮对话留档、每次开发先计划后实施。
> 启动动作：① 建立 `/docs` 目录与模板；② 写入本轮对话并提交双仓；③ 产出 M1 plan 与 design 并提交双仓；
> ④ 输出 monorepo 结构、双远程配置步骤、数据 schema（含版本）、shared 包设计、M1 实现计划与关键代码骨架。

原话摘录（铁律部分）：

> 1. 每次对话都应留档……形成可追溯的对话档案。
> 2. 每次开发都应先设计计划、方案并留档，再实施……禁止"先写代码后补文档"。
> 3. 文档留档是交付物的一部分，缺失文档视为任务未完成。
> 4. 以上铁律优先级高于进度要求：宁可延期，不可无档开发。

## 3. 讨论与决策

| 编号 | 议题 | 结论 | 依据 / 关联 |
| --- | --- | --- | --- |
| D1 | 仓库组织方式 | 采用 **pnpm workspaces monorepo**；M1 不引入 Turborepo，M2 视构建耗时再评估 | ADR-0001 |
| D2 | 移动端技术选型 | **React Native + Expo（dev build / prebuild）+ `@maplibre/maplibre-react-native`**，一套代码出 Android / iOS | ADR-0001 |
| D3 | Web 技术栈 | React 18 + TypeScript(strict) + Vite + MapLibre GL JS + Tailwind CSS + Zustand | ADR-0001 |
| D4 | 共享层边界 | `packages/shared` **纯 TypeScript，不依赖 DOM / React / RN**；数据加载通过注入 `fetch` 实现，天然适配 Web 与 RN | ADR-0001、design §5 |
| D5 | 数据契约版本 | 定为 **atlas-schema v1.0.0**，`manifest.schemaVersion` 必填；语义化版本，MINOR 只增不改，MAJOR 需迁移脚本 | ADR-0002 |
| D6 | 多语言字段 | 引入 `LocalizedString = string \| { zh: string; en?: string }`，v1.0.0 起生效；UI i18n 延后到 M3 | ADR-0002 |
| D7 | 时间表示 | 统一 **UTC 日粒度 epoch 毫秒**（`Date.UTC`），`shared` 内不引入 dayjs/date-fns，刻度与格式化自研纯函数；展示层用 `Intl.DateTimeFormat` | design §4.4 |
| D8 | 地图底图 | MapLibre style **可配置**（`VITE_MAP_STYLE_URL`）；默认使用 OSM 栅格瓦片，天地图/MapTiler 作为可选配置，密钥走环境变量不入库 | design §7 |
| D9 | 状态管理 | Web 端 Zustand 单 store（atlas / timeline / ui 三个 slice）；shared 只暴露纯函数与选择器 | design §5 |
| D10 | M1 示例数据 | 「长征」专题：**6 段路线 + 24 个事件**，含 sources；标注「数据初稿，待史料校订」 | plan §4 T9 |
| D11 | 双仓策略 | `origin` 指向 GitHub，并追加 Gitee 为第二 `pushurl`，`git push origin` 双推；tag 双仓同步 | ADR-0003 |
| D12 | 移动端在 M1 的范围 | 仅建立可安装的空壳工程（Expo 配置 + 占位首页），地图与时间轴在 M4 落地，避免 M1 膨胀 | plan §2 |

**分支规范化说明**：两仓初始化时默认分支不同（GitHub `main`、Gitee `master`），且各自只有一个 `LICENSE` 初始提交（版权署名分别为 `roma007` / `roma`）。处理方式：

1. 以 GitHub `main` 的初始提交为基线 rebase 本地提交，保留 `LICENSE`（署名 `roma007`）。
2. `git push origin main` 双推，Gitee 新增 `main` 分支。
3. `git push --force-with-lease gitee main:master` 将 Gitee 默认分支 `master` 快进到同一提交，使 Gitee 首页默认展示完整项目。
4. 后续统一以 **`main`** 为开发分支；Gitee 的 `master` 视为镜像分支，不再单独提交。建议用户在 Gitee 仓库设置中把默认分支改为 `main`，之后可删除 `master`。
