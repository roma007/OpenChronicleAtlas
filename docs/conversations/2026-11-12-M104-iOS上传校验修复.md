# 对话档案：M104 iOS 上传校验修复

- **日期**：2026-11-12
- **参与者**：用户（项目负责人）、AI 开发助手（DeepSeek V4.1 Flash / OpenCode）
- **关联里程碑**：M104（iOS 上架修复，版本 `1.0.3`）
- **关联文档**：
  - [CHANGELOG v1.0.3](../changelog/CHANGELOG.md)
  - [发布前检查清单](../releases/release-checklist.md)

## 1. 问题

Xcode 上传 App Store Connect 时报错：

> Invalid Info.plist value. The value of the LSMinimumSystemVersion Info.plist key in the com.openchronicle.atlas bundle, 16.4, is invalid. It must specify an operating system version of 26.0 or later, or a version earlier than 16.0. (91164)

同时出现三条 `Upload Symbols Failed`：

- `React.framework`
- `ReactNativeDependencies.framework`
- `hermesvm.framework`

## 2. 原因

| 问题 | 原因 |
| --- | --- |
| 91164 | `LSMinimumSystemVersion` 是 macOS 键，iOS Info.plist 不应设置；16.x 会被上传校验拒绝 |
| dSYM 警告 | RN 0.88 / Expo 58 使用预编译 React Native Core 与 Hermes 二进制，产物未附带这三者 dSYM |

## 3. 处理

- 从 `app.config.ts` 的 `infoPlist` 中移除 `LSMinimumSystemVersion`。
- Expo 模板仍会写入默认值 12.0，因此新增 `plugins/with-remove-macos-plist.js`，在 prebuild 后删除该键。
- iOS 最低版本仍由 `IPHONEOS_DEPLOYMENT_TARGET = 16.4` 与 `MinimumOSVersion` 决定。
- 版本升级到 `1.0.3` / build `10003`。

## 4. dSYM 说明

`Upload Symbols Failed` 不阻塞上传，但会影响这三者在崩溃报告中的符号化。

可选方案：

1. 接受警告，先完成首次上架；
2. 在 `expo-build-properties` 中启用 `ios.buildReactNativeFromSource: true`，从源码构建 React Native 与依赖，换取 dSYM（构建时间显著增加）；
3. Hermes 预编译框架仍需单独确认 dSYM 来源。

## 5. 验证

- Info.plist 不再包含 `LSMinimumSystemVersion`。
- 版本 `1.0.3 (10003)`。
- Xcode 26.6 Release 构建通过。
