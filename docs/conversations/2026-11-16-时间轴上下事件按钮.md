# 对话档案：时间轴「上一事件 / 下一事件」按钮

- **日期**：2026-11-16
- **参与者**：用户（项目负责人）、AI 开发助手（DeepSeek V4.1 Flash / OpenCode）
- **关联**：[长征台账](../research/route-endpoints/long-march.md)、[陕北红军全史补全](2026-11-16-陕北红军全史补全.md)

## 1. 需求

> 在时间轴栏增加上一个按钮和下一个按钮，点击切换事件节点

## 2. 实现

Web 与移动端各加一对按钮，紧跟在播放按钮后面（`‹` / `›`）。

行为：

- 候选事件 = 当前实体选择 + 类别筛选后、且落在时间范围内的全部事件；
- 按事件起始日排序，**下一事件**取第一个起始日晚于当前时间的事件，**上一事件**取最后一个早于当前时间的事件；
- 点击后：暂停播放 → 把时间轴移到该事件起始日 → 选中该事件并打开详情面板；视口若不在范围内会自动居中；
- 到达首 / 末事件时对应按钮禁用；
- 悬停（Web）或无障碍提示（移动端）显示目标事件名。

同一天有多个事件时按时间跳转，避免连续点击时间不动；详情面板里的「上一事件 / 下一事件」仍按事件逐条切换。

## 3. 顺手修的数据问题

测试按钮时发现：长征专题的 `timeRange.start` 还是 `1934-02-01`，但 `1.0.74` 加入的包家寨会议是 `1933-11-03`，落在时间范围之外——时间轴看不到，按钮却把「上一事件」指向它。

处理：

- `timeRange.start` 改为 `1933-10-12`（照金失守后红军主力北上的起点）；
- 副标题改为 `1933—1936`，描述首句补「1933 年 10 月至 1934 年 1 月为陕北、陕甘边苏区前史」；
- 前端同时加了范围过滤，范围外的事件不会进入按钮候选。

## 4. 验证

- `pnpm typecheck`、`pnpm lint` 通过；
- `pnpm validate:data`：11 专题 / 911 事件 / 654 路线段；
- 浏览器实测（`/atlas/long-march`）：
  - 起点 1933-10-12：「上一事件」禁用，「下一事件」→ 包家寨会议；
  - 再点「下一事件」→ 1934-02-01 陕甘边第一次反「围剿」，「上一事件」恢复可用；
  - 点「上一事件」回到包家寨会议，详情面板同步打开；
  - 按 End 到 1936-10-22：「下一事件」禁用，「上一事件」→ 会宁会师。
