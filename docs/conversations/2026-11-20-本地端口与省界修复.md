## 1. 原始需求

> 这个项目的本地网站是不是跟本电脑其他项目的本地网站有冲突？又不能访问了。

> 海南岛内的红色疆界好像有问题，有3条直线，其中有两条横跨海南岛，三条几乎形成一个大三角形。

> 历史省界有时候会消失，需要缩放地图才再次显示。

## 2. 本轮产出

### 2.1 本地开发端口

- Web 开发端口从 5173 改为 **5180**，`strictPort` 保留；
- 支持 `VITE_DEV_PORT=5181 pnpm dev` 临时换端口；
- README 与 AGENTS 增加本地开发说明，并注明本机 8081 可能是其他项目（Expo），Atlas 线上预览是 `quizgo-ecs:8081`。

### 2.2 海南岛省界三角形

- 根因：`roc-provinces.geojson` 中广东的海南环含一段北岸重复弧，简化后出现两条跨岛斜线；
- 修复：按 >100km 跳跃切开环，保留面积最大的闭合子环，四张快照全部修复；
- 防复发：`import-roc-provinces.py` 内置同样修复，`check-region-index.ts` 增加 >150km 直线回归检查。

### 2.3 历史省界消失

- 根因：`useI18n()` 每次渲染都返回新的 `t` 函数，而 `MapCanvas` 的疆域/地区标注重建 effect 把 `t` 放进了依赖数组；
- 任何无关重渲染（悬停省名出提示、选中事件等）都会触发整层重建，重建时多边形先 `hide()` 再等可见性 effect 显示；
- 可见性 effect 的依赖没变就不会重跑，于是整层省界停在隐藏状态，直到缩放改变 `zoom` 才恢复；
- 修复：
  - `t` 用 `useCallback` 按 `locale` 固定引用；
  - 抽出 `applyTerritoryVisibility` / `applyRegionLabelVisibility`，重建后立即同步一次可见性，不再依赖 effect 执行顺序。

## 3. 决策

| 编号 | 议题 | 结论 |
| --- | --- | --- |
| D1 | 是否继续用 5173 | 改用 5180，避免与其他 Vite 项目抢端口；被占用直接报错 |
| D2 | 海南环修复方式 | 切开长跳跃、保留最大闭合子环；不手工重画海岸线 |
| D3 | 省界消失的修法 | 稳定 `t` 引用 + 重建后立即应用可见性，双保险 |
| D4 | 是否为重建顺序加测试 | 无 React 测试依赖；以代码层双保险替代，回归检查留在 `check:regions` |
