- **参与者**：用户（项目负责人）、AI 开发助手（DeepSeek V4.1 Flash / OpenCode）

- **关联文档**：

## 1. 原始需求

用户：

> 提交必须更新服务器，这是铁律，写入 agent.md。然后更新到服务器，然后继续补下一批数据。

## 2. 结论

原流程把「提交」与「发布」分开，`git commit` / `git push` 不会更新 `/srv/atlas`。用户要求改为：

- **每次提交都必须同时更新服务器**；
- 只 commit / push 不算完成；
- 发布被 `/srv/ops` 请求或漂移检查硬拦时，先处理或显式 `--ack-open`，不得跳过。

## 3. 落地

### 3.1 AGENTS.md

- 第 2 节「提交铁律」新增：提交后必须执行 `pnpm release`，完成构建、备份、同步、自检与 `/srv/ops` 登记。
- 第 7.1 节「什么时候必须更新服务器」改为：自 v1.0.14 起，每次提交都发布，不再按「用户能否看出区别」攒发布；只改文档、纯重构也必须发。

### 3.2 发布

- 本次先提交 AGENTS.md，版本由钩子升到 `1.0.14`；
- 随后执行 `pnpm release`，把 `1.0.14` 同步到 `/srv/atlas`；
- 发布后按第 7.3 节四条自检，并确认 `status.sh` 漂移检测全绿。

## 4. 影响

- 以后每个 commit 都要跟一次 release，发布频率提高；
- 纯文档提交也会更新服务器，线上 About 版本会持续前进；
- 发布脚本的硬拦（工作区、跨项目请求、共享面漂移）成为提交完成的一部分。

## 5. 验证

- `pnpm check:versions`：1.0.14 / build 10014；
- `pnpm release`：构建、回滚点、rsync、四条自检、state/journal 登记；
- `ssh quizgo '/srv/ops/bin/status.sh'`：漂移检测全绿。

- [ ] 发布失败时按第 7.4 节回滚，不允许只推代码不发布。
