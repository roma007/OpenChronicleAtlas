- **日期**：2026-11-23
- **参与者**：用户（项目负责人）、AI 开发助手
- **关联版本**：v1.0.264
- **关联文档**：[CHANGELOG](../changelog/CHANGELOG.md)、[M281 时间轴性能](2026-11-23-京杭大运河时间轴性能M281.md)

## 1. 用户的问题

「可是这就导致日期值都是 XX 年 1 月 1 日。」

M281 把千年跨度的时间轴从 47 万个日刻度改成 7 个年刻度后，日期显示仍然按「日」精度输出：

- 时间轴两端：`605年1月1日`、`1901年6月1日`；
- 事件详情：`960年1月1日`；
- 搜索结果的日期：`605-01-01`；
- 日期跳转框仍是 `YYYY/MM/DD`。

京杭大运河的数据本来只精确到年，`01-01` 只是占位，继续显示「1月1日」会让人误以为有确切月日。

## 2. 改法

### 通用日期精度

`formatDate(t, locale, precision)` 增加第三个参数：

- `year` → `960年` / `960`
- `month` → `960年1月` / `January 960`
- `day` → `960年1月1日` / `January 1, 960`

默认仍是 `day`，不影响其他专题。

### 专题级精度

京杭大运河 `manifest.json` 增加：

```json
"extensions": { "datePrecision": "year" }
```

事件、路线、时间轴、搜索索引都读取这个值。

### 显示位置

- 时间轴起点、终点、游标日期：`605年`、`1901年`、`960年`；
- 事件详情与事件气泡：`960年`；
- 地区筛选里的事件日期：`960年`；
- 路线详情的起止日期：`1289年 — 1293年`；
- 搜索结果日期：`960年`；
- 日期跳转框：年精度专题改为「跳转到年份」的数字输入，范围 605—1901。

## 4. 备注

- 其他专题没有设置 `datePrecision`，继续按日显示，行为不变。
- 搜索索引为年精度事件写入 `datePrecision: "year"`，日精度事件不写，避免索引膨胀。
- 这次没有改事件日期本身；`0605-01-01` 仍是存储格式，只是显示时不再把占位的月日当真实日期。
