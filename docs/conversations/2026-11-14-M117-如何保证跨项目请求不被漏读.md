# M117 如何保证跨项目请求不被漏读

- **日期**：2026-11-14
- **时间**：18:30
- **参与者**：用户（项目负责人）、AI 开发助手（OpenCode）
- **关联里程碑**：M117
- **关联文档**：`AGENTS.md` 第 7、8 节，`scripts/deploy.sh`，`/srv/ops/CONTRACT.md`

## 1. 原始需求（用户原话摘要 / 引用）

> 「他或你的请求，你或他如何才能自觉去读而不会漏过呢？」

问题实质：M116 建了 `/srv/ops/requests/`，但「记得去看」仍是自觉行为，等于没解决。

## 2. 需求拆解

| 编号 | 需求点 | 类型 | 优先级 |
| --- | --- | --- | --- |
| R1 | 读请求不能依赖记忆，要有强制触发点 | 机制 | P0 |
| R2 | 触发点不能阻塞正常开发 | 约束 | P0 |
| R3 | 不能因为对方长期不处理就堵死本仓库 | 约束 | P0 |
| R4 | 离线或服务器不可达时仍能提交 | 约束 | P1 |
| R5 | 要说清机制的能力边界，不夸大 | 文档 | P0 |

## 3. 讨论与决策

| 编号 | 议题 | 结论 | 依据 |
| --- | --- | --- | --- |
| D1 | 只写进 AGENTS.md 够不够 | 不够。AGENTS.md 会被自动加载，但「读到规则」≠「执行动作」 | 用户此问正是针对这一点 |
| D2 | 用什么做强制点 | 挂在**每次都会发生**的动作上：git 提交、发布、看服务器状态 | 这三件事本来就绕不开 |
| D3 | 提交时拦截还是提示 | **只提示**。请求可能长期挂在对方，拦截会把本仓库堵死 | R3 |
| D4 | 发布时拦截还是提示 | **硬拦**，需 `--ack-open` 显式放行 | 发布改变线上，值得停下来确认 |
| D5 | 是否用 sshd Banner 强制每连接可见 | 暂不做 | 需改 sshd（服务器红线内配置），且 Banner 是 pre-auth，会向前置身份泄露内部信息 |
| D6 | 超时未处理是否升级 | 暂不做字段升级；`inbox.sh` 输出已带 age（小时） | 先够用 |

## 4. 三条自动触发路径

| 触点 | 时机 | 行为 |
| --- | --- | --- |
| `.githooks/pre-commit` | 每次 `git commit` | 列出给 atlas 的未处理请求（不阻塞） |
| `pnpm release`（`scripts/deploy.sh`） | 每次发布 | 有未处理请求 → `exit 2`，除非 `--ack-open` |
| `status.sh` | 任何服务器操作前后 | 版本 / 漂移 / 待办一屏看完 |

另有 `pnpm ops:inbox` 随时手动查。三次触点覆盖了「提交」「发布」「看服务器」三种典型开工方式。

## 5. 本轮产出

- `scripts/ops-inbox.sh`（`pnpm ops:inbox`）：本地薄封装，离线静默跳过。
- `scripts/deploy.sh`（`pnpm release`）：第 7 节的完整实现，三道闸门（脏工作区 / 跨项目请求 / 漂移告警）+ 自动登记。
- `/srv/ops/bin/inbox.sh`：服务器侧按项目过滤请求，输出带等待时长。
- `.githooks/pre-commit`：新增 inbox 提示。
- `AGENTS.md`：§7.2 以脚本为主路径；§8 新增「为什么不会漏」与边界说明。

## 6. 边界（明确写进文档）

机制只提供**可见性**，不提供**强制**：

- AI 不碰 git、不发布、也不看服务器 → 仍然看不到请求
- 服务器不可达时钩子静默跳过（离线提交优先）
- 锁只能防同时改，防不了故意不拿锁

补强方向（未做）：sshd Banner 每连接提示、请求超时自动升级为 `incident`、
两边都接入后把「发布未登记」挂进 CI。
