# 对话档案：路线表现更生动

- **日期**：2026-11-17
- **参与者**：用户（项目负责人）、AI 开发助手（DeepSeek V4.1 Flash / OpenCode）
- **关联**：[M160 方案](../plans/2026-11-17-M160-路线动态表现增强-design.md)、[M160 计划](../plans/2026-11-17-M160-路线动态表现增强-plan.md)

## 1. 需求

> 目前的线路表现方式太死板了，有没有更生动的表现形式？

## 2. 需求拆解

| 编号 | 需求点 | 类型 | 优先级 |
| --- | --- | --- | --- |
| R1 | 路线在时间轴推进时能看出“正在走” | 功能 | 高 |
| R2 | 出发前后有层次：未走 / 在走 / 走完 | 功能 | 高 |
| R3 | 提供可对比的两种实现，先看效果再定 | 流程 | 高 |
| R4 | 不破坏时间轴、标记、聚合、疆域、分享链接 | 约束 | 高 |

## 3. 讨论与决策

| 编号 | 议题 | 结论 | 依据 |
| --- | --- | --- | --- |
| D1 | 改矢量覆盖物还是另起画布层 | 先各做一版原型，`?routes=vector` / `?routes=canvas` 切换 | 只靠静态截图无法判断动效 |
| D2 | 动效清单 | 首批：预告线、线头、尾迹、抵达涟漪、悬停浮签；第二批：压暗聚焦、缩放线宽、军标节点、镜头跟随 | 分批降低回归面 |
| D3 | 画布版是否保留 | 用户选定矢量增强版后，删除画布层、临时开关与相关工具函数 | 常态 30fps 重绘成本高，维护面大 |
| D4 | 未做的三项 | 节点军标、镜头跟随、stroke-in 暂不做 | 改变信息密度/操作权，或与时间轴语义重叠，需单独评估 |
| D5 | 拖动时间轴为什么没有播放时的效果 | 线头、预告线、尾迹本来就会跟随；涟漪原先只在播放触发，压暗仍是播放专属。按用户要求开放拖动涟漪，并做限流 | 快速拖动时避免满屏涟漪 |
| D6 | 拖动时是否也压暗已走完的线 | 是。拖动期间临时进入「聚焦当前」，松手立即恢复全彩，避免静态阅读时整图发灰 | 与播放态观感一致 |
| D7 | 拖动时为什么不弹当前节点气泡 | 气泡原先只在播放时触发；改为播放与拖动都弹，拖动间隔降到 120ms，松手后保留到 4s 计时结束 | 拖动时也能看到节点信息 |

## 4. 疑问与答复

| 编号 | 疑问 | 答复 | 状态 |
| --- | --- | --- | --- |
| Q1 | 流光效果能否用矢量实现 | 只能用虚线偏移做近似；真正的流光留在将来专题片头的短时画布层 | 已确认 |
| Q2 | 画布版会不会在手机上耗电 | 暂停也持续 30fps 重绘，需可见性与低端机门控，因此不选为默认实现 | 已确认 |
