## 1. 原始需求

用户：

> 继续

M20 的发布检查清单发现几项内部可修复的发布阻塞：iOS 版本号仍为 0.5.0、Android 主 manifest 仍允许明文流量并保留 `SYSTEM_ALERT_WINDOW`、缺少版本一致性检查。本轮进入 M22：内部阻塞修复。

## 2. 本轮范围

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| F1 | iOS 版本号对齐 | `0.21.0` / build `18` |
| F2 | iOS 最低系统对齐 | `LSMinimumSystemVersion` 16.4 |
| F3 | Android 主 manifest 关闭明文流量 | debug 仍允许本地调试 |
| F4 | Android 移除悬浮窗权限 | 主 manifest 移除，debug 保留 |
| F5 | 版本一致性检查脚本 | `pnpm check:versions` |
| F6 | 文档与版本 | `v0.22.0-m22` |

不在本轮范围：APK/IPA 打包、商店提审、域名、高德许可。

## 3. 关键决策

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| D1 | 主 manifest 关闭明文流量 | 生产合规 |
| D2 | debug manifest 保留明文 | 本地 `10.0.2.2` 调试 |
| D3 | 悬浮窗权限仅 debug 保留 | 开发工具需要，生产不需要 |
| D4 | 新增版本检查脚本 | 防止三端版本再次漂移 |
| D5 | 不改业务代码 | 降低风险 |

## 4. 验收

- iOS plist 版本与源码一致；
- 主 manifest `usesCleartextTraffic=false`，debug 为 true；
- 主 manifest 无 `SYSTEM_ALERT_WINDOW`；
- `pnpm check:versions` 通过；
- `pnpm lint`、`pnpm typecheck`、`pnpm test`、Web 构建通过；
- 版本 `0.22.0`，双仓 tag `v0.22.0-m22`。
