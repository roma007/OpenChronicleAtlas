## 1. 为什么先做这件事

分省补县做到 M251 后，事件层只剩 1 条「待考」描述，但路线层仍有 48 段写着
「待史料校订 / 待页码核对」。其中 #3 存在**史实错误**：把 1937 年日军画成由北平经徐州
直抵南京（徐州 1938-05-19 才失守，南京系由淞沪方向攻陷）。按「宁可少一条，不可错一条」，
这比继续加县更要紧。

## 2. 处置

| 路线 | 处置 |
| --- | --- |
| #3 | 改为「北平—保定—石家庄—邢台—邯郸—安阳（平汉线北段）」，起止 1937-07-07 ~ 11-05，起点前推至卢沟桥；注明南京见 #5 |
| #5 | 补「8-13 淞沪会战 / 11-12 上海失守 / 12-13 南京失守」 |
| #46 | 明确「战役总览，非单次行动」，列出 #282/#284/#293/#295/#297/#298 分段线 |
| #15 | 853 天收紧至 1938-07-01 ~ 07-31（1938 年 7 月中条山作战） |
| #1 | 标为 `precision: campaign`（分期占领总览） |
| #23、#77 | 删除（与 #289、#203/#204 同日同起止的重复粗线） |

## 3. 两个技术坑

1. **删路线必须先重建 regionIndex**：删 #15 后未重建，`validate:data` 报
   「regionIndex 引用了不存在的路线」，并把整个专题统计为 0 事件，一度看起来像数据损坏。
2. **删粗线前先确认事件覆盖**：删 #15 后「日军进攻中条山（1938）」立即失去活动路线
   （`check:routes` 报 547km），因此改为收紧时间跨度而非删除；删 #23/#77 前确认
   #289、#203/#204 覆盖相应事件日期。

## 4. 验证

```bash
python3 scripts/build-region-data.py
pnpm validate:data
pnpm check:routes --atlas anti-japanese-war
pnpm check:heads --atlas anti-japanese-war
pnpm build:search-index
pnpm build:mobile-data --check
pnpm typecheck && pnpm lint && pnpm test
```

结果：1025 事件 / 562 路线，0 个路线-事件超距，0 个无来由端点，全部通过。
