## 1. 原始需求

用户：

> 继续

M8 已完成离线与弱网。当前搜索页仍标注「子串匹配，暂不支持拼音与分词」。本轮进入 M9：检索增强，支持中文拼音、首字母与中英文混合查询。

## 2. 本轮范围

| 编号 | 功能 | Web | 移动端 |
| --- | --- | --- | --- |
| F1 | 全拼搜索（zunyi → 遵义） | ✅ | ✅ |
| F2 | 首字母搜索（zy → 遵义） | ✅ | ✅ |
| F3 | 中英文混合搜索 | ✅ | ✅ |
| F4 | 拼音匹配排序低于原文匹配 | ✅ | ✅ |
| F5 | 搜索提示文案更新 | ✅ | ✅ |

不在本轮范围：分词、纠错、同义词、别名数据、APK/IPA 打包。

## 3. 关键决策

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| D1 | 使用 `pinyin-pro` 生成拼音 | 纯 JS、三端可用、维护活跃 |
| D2 | 索引中保存全拼与首字母 | 查询时无需实时转换 |
| D3 | 原文匹配权重高于拼音匹配 | 保证「遵义」优先于拼音命中 |
| D4 | 首字母权重低于全拼 | 减少 `zy` 之类短查询的误命中 |
| D5 | 拼音命中时片段回退原文 | 避免在中文文本中高亮拼音 |
| D6 | 不引入分词/纠错 | 控制范围与包体 |

## 4. 验收

- 搜索 `zunyi`、`zy`、`zunyi huiyi` 均能命中遵义会议；
- 搜索 `Zunyi`、`Key meeting` 仍命中；
- 原文「遵义」排序高于拼音命中；
- 搜索提示文案更新；
- 共享测试、Lint、Typecheck、Web 构建通过；
