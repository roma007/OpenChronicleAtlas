## 1. 原始需求

用户：

> 目前是不是只有网页端？如果是，增加 iOS 端、iPad 端、安卓端、macOS 端、Windows 端，又或者可以合并端，我的目的是要发布到苹果的 app store connect、微软市场和华为等安卓市场。

补充确认：

- 桌面端采用 Tauri 2 复用 Web；
- 已有 Apple Developer 与华为开发者账号；
- 暂无 Microsoft Partner Center 账号。

## 2. 现状判断

- 不是只有网页端：`apps/web` 与 `apps/mobile` 已存在；
- `apps/mobile` 使用 Expo + React Native，已覆盖 iOS / iPadOS / Android；
- 真正缺失的是 macOS / Windows 桌面端与商店提交流水线。

## 3. 决策

| 决策 | 结论 | 原因 |
| --- | --- | --- |
| 移动端 | 保留 Expo/RN | 高德原生 SDK 已在用，iPad 只需一个通用包 |
| 桌面端 | 新增 Tauri 2 | 复用 Web UI，包体小，系统 WebView 可直接跑高德 JS API |
| 不采用 Electron | — | 包体与内存开销大，无 Node 主进程需求 |
| 不采用 RN macOS/Windows | — | `expo-gaode-map` 无桌面实现，维护成本高 |
| 鸿蒙 NEXT | 暂不做 | 不兼容 APK，需独立 ArkTS/HAP 工程 |

## 4. 本轮交付

- `apps/desktop`：Tauri 2 工程、图标、能力配置、macOS entitlement；
- Web `desktop` 构建模式：关闭 PWA、HashRouter、系统浏览器打开外链；
- iPad 四方向与分屏 config plugin，图鉴页在 iPad 宽度下自动 2–3 列；
- `apps/mobile/eas.json` 与本地 AAB/APK 脚本；
- GitHub Actions 桌面构建工作流；
- Apple / 华为 / 微软提交指南；
- 桌面端独立高德 Key（`VITE_AMAP_DESKTOP_*`）与 `scripts/set-github-secrets.sh`；
- README、CHANGELOG、发布检查清单更新。

## 6. 未完成 / 阻塞

1. Windows 构建未在本机执行（需 Windows 或 GitHub Actions）；
2. Mac App Store 提审需 Team ID、证书、Provisioning Profile；
3. Microsoft Store 需 Partner Center 账号；
4. 华为 AppGallery 需软著、APP 备案、实名认证材料；
5. 高德商用许可与正式域名仍是外部阻塞；
6. HarmonyOS NEXT 原生端未覆盖。
