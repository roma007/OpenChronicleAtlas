## 1. 里程碑目标回顾

为静态专题数据增加内容版本号，并在 Web 与移动端检测到新数据时提示用户刷新，避免长时间使用旧缓存。

## 2. 交付内容

### 2.1 构建期数据版本

- `scripts/build-search-index.ts` 根据全部专题的 manifest / routes / events 生成 SHA-256 指纹；
- 版本格式：`YYYY-MM-DD-<12 位哈希>`；
- 写入：
  - `data/atlases/index.json`；
  - `data/atlases/search-index.json`；
- 只有数据变化时版本才变化，仅代码/文档构建不会误报。

### 2.2 共享层

- `AtlasIndex.dataVersion?: string`；
- `SearchIndexFile.dataVersion?: string`；
- 新增 `isDataVersionNewer(current, incoming)`：
  - 任一为空不提示；
  - 版本不同即提示，兼容回滚。

### 2.3 Web 更新提示

- store 增加 `dataVersion`、`dataUpdateAvailable`、`checkDataUpdate`、`applyDataUpdate`；
- 新增 `DataUpdatePrompt`：
  - 每 5 分钟检查；
  - 页面回到前台时检查；
  - 显示「数据已更新」与「刷新」；
  - 刷新使用 `window.location.reload()`。

### 2.4 移动端更新提示

- store 增加数据版本状态与检查/应用动作；
- 首页加载完成后检查，AppState 回到前台时检查；
- 横幅显示「数据已更新」与「刷新」；
- 刷新时清除专题缓存并重新加载首页。
