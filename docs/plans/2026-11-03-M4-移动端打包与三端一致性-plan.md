## 1. 目标（Goal）

把 Web 端已验证的专题浏览、时间轴、详情、搜索、筛选、分享能力搬到 **Android 与 iOS**，
复用同一套 shared 逻辑与同一套 `/data/atlases` 数据，并产出可安装的 **APK/AAB** 与 **IPA**（或模拟器包），
完成三端交互一致性验收。

## 2. 范围（Scope）

### 2.1 包含

1. **T1 PoC**：`expo-gaode-map` 在 Expo SDK 58 / RN 0.88 / 新架构下的地图、Polyline、Marker、InfoWindow 验证。
2. 移动端应用结构：
   - React Navigation（native-stack）：专题列表 → 专题地图 → 搜索；
   - 地图页：高德地图、分色路线、事件 Marker、当前事件高亮；
   - 时间轴：拖动、播放/暂停、倍速、日期跳转、刻度自适应；
   - 详情：底部抽屉、Markdown、图片、来源、关联事件、分享；
   - 搜索/筛选：复用 shared 检索与筛选；
   - 深链与系统分享。
3. 数据：`EXPO_PUBLIC_DATA_BASE_URL` 指向同一套 `/data/atlases`，不打包副本。
4. 合规：高德 SDK 隐私同意、隐私政策入口、权限说明；Key 通过 Config Plugin 注入。
5. 打包：
   - Android：prebuild + Gradle release，产出 APK/AAB；keystore 在仓库外；
   - iOS：prebuild + Xcode archive / 模拟器构建；有账号则导出 IPA。
6. 三端一致性验收矩阵（交互、数据、视觉）。
7. 文档：M4 对话、plan/design、ADR、CHANGELOG、release、tag `v0.4.0-m4`。

### 2.2 不包含（Out of Scope）

- 上架商店、App Store 审核素材、正式图标/启动图（M5）。
- 定位/「我的位置」、导航、离线地图（M5 评估）。
- Universal Links / App Links（M5）。
- 移动端单元测试框架与 E2E 自动化（M4 以手工矩阵 + 构建验证为主）。
- 第二个专题（M5）。
- 后端账号、收藏、评论。

## 5. 实施步骤

1. **确认方案**：用户确认 plan/design/ADR-0007 与 Q1–Q6。
2. **T1 PoC**：安装 `expo-gaode-map`，`expo prebuild`，在 Android 模拟器与 iOS 模拟器验证地图/线/点/气泡；不通过则先评估回退方案。
3. **T2–T3**：导航、主题、数据客户端、store；确保与 Web 使用同一 shared API。
4. **T4–T6**：地图页 → 时间轴 → 详情抽屉，按 Web 行为对齐。
5. **T7–T8**：搜索/筛选/分享/深链。
6. **T9**：隐私同意、权限、Config Plugin、Key 注入。
7. **T10 Android**：配置签名、versionCode、`assembleRelease`，安装 APK 验证。
8. **T11 iOS**：模拟器构建；账号就绪则 archive + export IPA；否则交付未签名 archive 与说明。
9. **T12 验收**：三端矩阵、截图、CHANGELOG、release、双推、tag `v0.4.0-m4`。

## 6. 风险与应对

| 风险 | 影响 | 概率 | 应对 |
| --- | --- | --- | --- |
| `expo-gaode-map` 与 SDK 58/新架构不兼容 | 地图无法显示，M4 阻塞 | 中 | T1 先验证；回退 `react-native-amap3d` 或自定义 Expo Module；必要时降级新架构 |
| 无 Apple Developer 账号/证书 | 无法导出 IPA | 高 | 先交付 iOS 模拟器构建 + 未签名 archive；IPA 待账号就绪补 |
| Android Key 的 SHA1/包名不匹配 | 地图空白 | 中 | 用 release/debug SHA1 核对；必要时重新申请 Key |
| 真机访问开发机数据 URL 失败 | 无数据 | 中 | 使用 LAN IP + 同一 Wi-Fi；生产用部署后的 HTTPS 数据地址 |
| 高德 SDK 隐私合规未初始化 | 审核/合规风险 | 中 | 首次启动隐私弹窗，同意后初始化；隐私政策列出 SDK |
| iOS 构建签名/Provisioning 复杂 | 构建失败 | 高 | 先模拟器；Xcode 自动签名；EAS Build 备选 |
| RN 时间轴手势与 Web 不一致 | 体验差异 | 中 | 复用 shared 计算；交互矩阵逐项验收 |
| 低端 Android 地图卡顿 | 体验差 | 中 | 30fps 节流、减少 Marker 重建、必要时聚合 |
| 打包产物过大/密钥误入库 | 安全/交付 | 低 | `.gitignore` 覆盖 keystore/certs；构建产物不入库 |

## 7. 验收标准（DoD）

- [ ] `pnpm -r typecheck`、`pnpm lint`、`pnpm test`、`pnpm build`、`pnpm validate:data` 全部通过。
- [ ] Android APK 可安装并启动（API 26+），地图/路线/Marker/时间轴/详情/搜索/筛选/分享可用。
- [ ] iOS 模拟器构建可启动；如账号就绪，IPA 可安装并启动（iOS 14+）。
- [ ] 三端读取同一套 `/data/atlases`，无各端数据副本。
- [ ] 三端一致性矩阵通过：时间轴拖动/播放/倍速、路线生长、节点显隐/高亮、详情、筛选、搜索、分享。
- [ ] 移动端系统分享可调起；深链可恢复时间/事件。
- [ ] 隐私同意流程存在；高德 Key/证书/keystore 未入库。
- [ ] 文档齐全；双仓 HEAD 一致；tag `v0.4.0-m4`。

## 8. 回滚方案

- 移动端为新增实现；回滚保留 M1 空壳，不影响 Web。
- 若 `expo-gaode-map` 不兼容，回退地图库或暂以静态图 + 事件列表交付，时间轴/详情仍可用。
- 打包失败不影响代码交付；记录阻塞项与复现步骤。
