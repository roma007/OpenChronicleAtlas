# M157 路线端点铁律：无来由线头、无后续线尾一律拦下 — 方案

- **日期**：2026-11-16
- **里程碑**：M157（规则与工具）
- **状态**：内容已实施并通过校验
- **关联**：[M148 线头审计](2026-11-15-M148-线头审计-design.md)

## 1. 问题

过去几轮反复出现同一类缺陷：路线从某地凭空起头（沾益、马龙、镇宁、老木孔），或者到战场就断头（大树堡、忠堡、板栗园、陈家河）。靠人眼和临时审计脚本查，漏一次就要返工一次。

## 2. 铁律

写进 `AGENTS.md` 第 4 节第 8 条：

- 每段路线的**起点**必须满足其一：落在同实体另一段路线上（10km 内）、落在同实体事件上（10km 内）、或是该实体按日期排序的第一条路线；
- **终点**同理：接上后续路线、落在事件上、或是该实体的最后一条路线；
- 防线、航线、补给线、国民党军追击/封锁线不适用；
- 史实终点无法接线的，写进该专题 `route-endpoints.allow.json` 并注明原因，禁止口头豁免、禁止调大阈值绕过；
- 每次改动路线后运行 `pnpm check:heads`，0 个问题才允许提交。

## 3. 工具

新增 `scripts/check-route-endpoints.ts` 与 `pnpm check:heads`：

```
pnpm check:heads                # 默认 long-march
pnpm check:heads --atlas <id>   # 单个专题
pnpm check:heads --all          # 全部专题
pnpm check:heads --threshold 10 --json
```

判定逻辑：

1. 按实体分组，按日期排序；
2. 跳过 `kmt-*` 实体、`defense` / `naval` / `supply` 段；
3. 跳过每个实体的第一条路线起点、最后一条路线终点；
4. 其余端点计算到同实体其它路线折线、同实体事件的最短距离；
5. 两者都超过阈值（默认 10km）且不在 allowlist 中，记一个问题并退出码 1。

## 4. 强制执行

| 触点 | 方式 |
| --- | --- |
| AI 每次实施 | `AGENTS.md` 自动加载，规则在第 4 节第 8 条 |
| 每次提交 | `.githooks/pre-commit`：有路线文件改动时，对改动的专题跑 `pnpm check:heads --atlas <id>`，失败即拒绝提交 |
| 每次发布 | `scripts/deploy.sh` 前置检查新增 `pnpm check:heads` |
| 人工排查 | `pnpm check:heads --all` 可列出全部专题的存量问题 |
