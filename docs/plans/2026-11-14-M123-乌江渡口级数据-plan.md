## 1. 背景

强渡乌江目前只有一个县域示意点，没有拆出江界河、回龙场、茶山关三个渡口，也没有独立的黔军防线节点。

## 2. 目标

1. 新增江界河、回龙场、茶山关 3 个渡口事件；
2. 修正强渡乌江、国民党军乌江防线的坐标与描述；
3. 新增乌江渡口群 defense 路线，补路线 10 的江界河控制点；
4. 重新生成搜索索引与移动端内置数据映射；
5. 提交并发布到服务器（按提交铁律）。

## 3. 范围

### 3.1 包含

- `data/atlases/long-march/events/events.json`
- `data/atlases/long-march/routes/central-red-army.geojson`
- `data/atlases/search-index.json`
- `data/atlases/index.json`
- `apps/mobile/src/generated/atlasData.ts`
- 本轮 docs 与 CHANGELOG

### 3.2 不包含

- 其他专题；
- schema 变更；
- UI 渲染逻辑；
- 孙家渡、袁家渡等其他渡口的逐点落位；
- 版本号手动修改。

## 5. 实施步骤

1. 记录本轮需求与点位口径；
2. 按江界河、回龙场、茶山关补事件；
3. 修正强渡乌江、国民党军乌江防线；
4. 补路线 10 江界河控制点，新增乌江渡口群 defense 路线，原 11—35 顺延为 12—36；
5. 运行 `pnpm validate:data`、`pnpm check:routes --atlas long-march`；
6. 运行 `pnpm build:search-index`、`pnpm build:mobile-data`；
7. 运行 `pnpm typecheck`、`pnpm lint`、`pnpm test`；
8. 更新 CHANGELOG，提交（钩子升版）、tag、推送；
9. 执行 `pnpm release`，更新服务器并登记。

## 6. 风险与应对

| 风险 | 影响 | 概率 | 应对 |
| --- | --- | --- | --- |
| 三个渡口无精确坐标 | 点位偏差 | 高 | 用渡口代表点，标 `approx` |
| 新增 defense 路线导致编号变化 | 文档引用错位 | 中 | 脚本统一顺延 11—35 |
| 击溃黔军数字统计不一 | 数字争议 | 中 | 采用「4 团 2 营约 4000 人」说 |
| 发布被 /srv/ops 请求阻塞 | 无法发布 | 低 | 先处理或显式 `--ack-open` |
