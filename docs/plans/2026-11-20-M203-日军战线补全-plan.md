# M203 日军战线补全计划

- 日期：2026-11-20
- 专题：`anti-japanese-war`
- 目标：以日军为行为主体，补齐 1931—1945 年进攻、登陆、占领、封锁、殖民统治、细菌战与受降节点，做到事件、路线、锚点、来源四者对应。
- 原则：**宁可标“待页码级核对”，不写没有出处的数字；宁可少一条，不造一条假线。**

## 1. 审计方法

1. 先按年份列出日军层现有事件与路线（当前 128 事件 / 64 段）。
2. 按作战类型建立覆盖矩阵：东北、华北、华中、华南、滇缅、沿海封锁、航空轰炸、细菌战、傀儡政权、资源掠夺、受降。
3. 再按“行为主体”复核：事件是否由日军发起；若事件已挂中国军队但日军是行为主体，补挂 `japanese-invasion` 或新增日军侧节点。
4. 与中国军队层、集团军层、华南游击队层交叉比对，避免同一事件重复造两条。
5. 每条新增事件必须有可核查的日期、地点、行为主体；无页码级来源的兵力、伤亡、产量数字一律不写具体数，只写“通行说法，待页码级核对”。

## 5. 验收标准

每批完成后必须全部通过：

```bash
pnpm validate:data
pnpm check:routes --atlas anti-japanese-war
pnpm check:heads --atlas anti-japanese-war
pnpm typecheck
pnpm lint
pnpm test
pnpm build:search-index
pnpm build:mobile-data
```

- `check:routes`：0 个问题；新增事件必须在同实体活动路线 30km 内，或明确 `routeEvent: false`。
- `check:heads`：0 个无来由端点；登陆点、边境入口等天然独立端点写入 `route-endpoints.allow.json` 并写明理由。
- 事件日期、地点、实体归属逐条对照来源；有异说的在 `description` 内注明，不隐藏。
- 新增路线必须有 `startDate` / `endDate` / `name` / `segmentType` / `precision`，并与事件日期重叠。
- 文档同步：专题 README、实体审计、路线审计、日期核对清单、CHANGELOG、会话记录。

## 6. 明确不补/暂缓

以下项经核查不属于“日军行为主体”或无法达到可考证标准，暂不补录，避免为凑数造事件：

- 日本国内内阁更迭、政党政治、经济统制细则。
- 伪政权内部的行政区划、人事更替（只保留政权成立这一层）。
- 无确切日期或地点的“扫荡”“清乡”传闻性数字。
- 与抗战主线无直接关系的太平洋战场战役（珍珠港、缅甸已作为中国抗战关联节点保留）。
- 日军各师团、旅团的完整序列（属于建军史，不是本专题的战役节点）。

## 7. 风险与口径

1. **日期异说**：郑州沦陷有 4/19、4/20、4/23 诸说；汕头有 6/21、6/22 诸说；福州有 4/21、4/22 诸说。统一在 `description` 内注明“通行说法/异说”，事件日期取档案或地方志中较具体者。
2. **路线精度**：登陆线、边境线为示意简化，`precision` 标 `schematic`；战役线标 `campaign`。
3. **端点豁免**：金山卫、闽江口、飞云江口等海上登陆起点，若 10km 内无同实体路线或事件，登记 `allow.json`，理由写“登陆点/海上锚地”，不得用调大阈值绕过。
4. **不造数字**：不写“歼敌 X 万”“掠夺 X 万吨”等无页码级出处的数字；必须写时标“通行说法，待页码级核对”。
