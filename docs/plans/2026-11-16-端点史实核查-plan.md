## 1. 基线

`pnpm check:heads --all` 当前 62 个无来由端点：抗日 37、明清 9、三国 6、宋元 5、隋唐 5；long-march 及其余 5 个专题为 0。

本计划不再按「距离远近」决定怎么接，而是按**历史战役/行动簇**逐条查：

- 线头：查这支部队此前在哪里、何时、经哪条路线到这里；
- 线尾：查这支部队此后去了哪里、何时、经哪条路线离开；
- 每条结论必须有可核对的出处。

## 4. 每条端点的标准流程（SOP）

1. 在 `docs/research/route-endpoints/<atlas>.md` 建一行，写清研究问题（前置/后续）；
2. 查来源，优先战史/军事志/档案，其次党史/地方志/纪念馆；
3. 写「史实结论」：谁、何时、从哪到哪、做了什么，附出处；
4. 判定处理：
   - 有明确行军记录 → 补前置/后续路线段（写名称、日期、描述、来源）；
   - 有明确日期地点 → 补事件；
   - 端点与地名不符 → 改坐标/拆段；
   - 记录证明此处就是起点/终点 → 登记 allowlist，附来源；
   - **查不到** → 台账写「已查，未得」并列出查过的来源，不画线；
5. 数据修改后跑 `validate:data`、`check:routes --atlas <id>`、`check:heads --atlas <id>`；
6. 更新索引、docs、CHANGELOG，提交并发布。

## 5. 验收标准

- [ ] 62 个端点在台账中都有「史实结论 + 出处」或「已查，未得 + 查过的来源」；
- [ ] 每条新增路线/事件都有来源，描述里能追溯到出处；
- [ ] 没有一条连接线是「为了通过检查」而画的；
- [ ] allowlist 只保留有据的独立端点，每条附来源；
- [ ] `pnpm check:heads --all` 归零；
- [ ] 每批一次提交与发布，文档同步。
