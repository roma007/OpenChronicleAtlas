## 1. 设计原则

1. **不改时间锚点**：每段路线的 `startDate`、`endDate`、首节点、末节点保持不变，事件-路线抽查结果不受影响。
2. **只加空间细节**：中间节点用于描述途经地，不引入新的事件或日期。
3. **保持示意属性**：所有新增节点仍属于「示意简化路线」，坐标取公开地名的近似中心点。
4. **来源可追溯但不虚构**：只使用常见权威通史、年谱、文献集；不写页码、不写未核实的 URL。

## 2. 中间节点规则

| 规则 | 说明 |
| --- | --- |
| 数量 | 每段 0—8 个中间节点，短段可不加 |
| 顺序 | 按行军方向排序，避免回头路与明显折线 |
| 精度 | 保留 2 位小数，与现有数据一致 |
| 首尾 | 必须与相邻段衔接，保持原起止坐标 |
| 校验 | 新增节点不得改变段首尾与事件坐标的距离 |

## 4. 史料来源策略

每个事件保留原有两条通史来源，并补充一条针对性来源：

| 事件类型 | 补充来源 |
| --- | --- |
| 重要会议 | 《毛泽东年谱（1893—1949）》，中央文献出版社 |
| 会师 | 《中国工农红军长征史料丛书》，解放军出版社 |
| 战役 / 战斗 | 《中国工农红军长征史料丛书》，解放军出版社 |
| 行军 | 《红军长征·文献》，解放军出版社 |

补充来源的 `note` 统一写明「用于核对〈事件名〉的日期、地点与路线走向」，避免声称具体页码。

## 5. 数据格式

沿用 `AtlasRouteFeature` 与 `AtlasSource`，不新增字段：

```json
{
  "geometry": {
    "type": "LineString",
    "coordinates": [[lng, lat], [lng, lat]]
  },
  "properties": {
    "entityId": "central-red-army",
    "startDate": "1934-10-10",
    "endDate": "1934-11-27",
    "order": 1
  }
}
```

3. `pnpm lint`、`pnpm typecheck`、`pnpm test`、Web 构建；
4. 对比修改前后段首尾坐标，确认未变化。

## 7. 兼容性

- 数据仍为 WGS84，渲染层继续转 GCJ-02；
- 时间轴、动画、搜索、筛选逻辑不变；
- 移动端读取同一静态数据，无需重新打包。
