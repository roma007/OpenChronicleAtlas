# 全量路线端点清理 — 方案

- **日期**：2026-11-16
- **里程碑**：M160（全量审计，分多批实施）
- **状态**：计划已建立，待分批实施
- **关联计划**：[2026-11-16-全量路线端点清理-plan.md](2026-11-16-全量路线端点清理-plan.md)
- **工具**：[M157 路线端点铁律](2026-11-16-M157-路线端点铁律-design.md)

## 1. 目标

`pnpm check:heads --all` 输出 **0 个无来由端点**，且不靠调大阈值、不靠虚构连接线。

「彻底消除」的准确含义：

- 每一段路线的起点，都能在同实体路线上、同实体事件上、或史料明确的出发地找到来路；
- 每一段路线的终点，都能接上后续、落在事件上、或史料明确的终点；
- 确属独立起点/终点的，写入 `route-endpoints.allow.json`，逐条注明原因与来源，**不是把问题藏起来**。

## 2. 判定分类

| 类型 | 特征 | 典型处理 |
| --- | --- | --- |
| A 近距断点 | 距最近路线或事件 <15km | 补一小段连接线，或把端点挪到既有节点 |
| B 中距断点 | 15—50km | 查史料，补短连接线或补事件锚点 |
| C 远距断点 | 50—150km | 多为坐标错位或漏了中间节点；改正坐标 / 补中间点 |
| D 超远断点 | >150km | 多为战役起点/终点（省会、边境、出海口）；补事件或登记 allowlist |
| E 数据错误 | 路线名与端点地名不符 | 改正坐标、拆段、改名 |

## 3. 处理顺序

每个端点按以下顺序尝试，前一步能解决就不进入下一步：

1. **补连接线**：史料支持两段之间确有行军/机动，补一段路线；
2. **补事件锚点**：端点是真实战斗/会师/渡口，补一个事件（比 allowlist 更有价值）；
3. **改坐标/拆段**：端点与地名明显不符，按可靠点位修正；
4. **allowlist**：确属独立起点/终点，且无史料可接，写 `reason` + `source`。

## 4. 反模式（禁止）

- 为了消掉线头，把两条不相干的路线硬接在一起；
- 把阈值从 10km 调到 50km 让检查通过；
- 用「示意」当借口，画一条没有史料支撑的连接线；
- allowlist 不写原因或只写「史实如此」。

## 5. 视觉语义

清理后，地图上仍会有「看起来像线头」的端点，它们分三类，均属正常：

- **实体第一条路线的起点**（根据地、出发城市）；
- **实体最后一条路线的终点**（会师地、终点城市）；
- **allowlist 中的独立战役起点/终点**（如 1685 年瑷珲、1942 年滇西反攻起点）。

判断标准是「有来路/有后续或有明确史料理由」，不是「视觉上必须闭环」。

## 6. 工具配套

现有 `pnpm check:heads` 已支持：

- `--atlas <id>`、`--all`、`--threshold <km>`、`--json`；
- allowlist：`data/atlases/<id>/route-endpoints.allow.json`，字段 `entityId`、`order`、`endpoint`、`reason`，建议再加 `source`。

计划中的小改进：

1. allowlist 校验增加 `source` 字段（可选但推荐）；
2. 输出时区分「未处理」与「已登记例外」，便于盘点；
3. 在 `status.sh` 或 CI 里加 `check:heads --all`（可选）。

## 7. 风险

| 风险 | 应对 |
| --- | --- |
| 为消除线头而虚构连接 | 每条新线必须有路线名/描述/来源；宁可 allowlist |
| 改坐标影响事件、搜索、路线 QA | 每批跑 validate:data、check:routes、check:heads |
| 一次改太多难以回滚 | 按专题分批，每批一次提交与发布 |
| 其它专题史料精度不足 | 以现有来源为限，不新造精确点位；标 approx |
