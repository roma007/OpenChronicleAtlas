## 1. 总体设计

```
buildSearchIndex
├── 原文：name / place / summary / description / category / entities / date
├── 全拼：pinyin(text, toneType: 'none') → "zun yi hui yi"
└── 首字母：每个音节首字母 → "zyhy"

searchEvents
├── 原文匹配：权重最高
├── 全拼匹配：次高
└── 首字母匹配：最低
```

## 2. 索引结构

扩展 `SearchEntry['fields']`：

```ts
interface SearchEntryFields {
  name: string;
  place: string;
  summary: string;
  description: string;
  category: string;
  entities: string;
  date: string;
  pinyin: string;
  initials: string;
}
```

- `pinyin`：所有中文文本的全拼，空格分隔；
- `initials`：每个汉字首字母连写，同时保留空格分词形式；
- 英文文本保持原样，不做拼音转换。

## 3. 拼音生成

使用 `pinyin-pro`：

```ts
import { pinyin } from 'pinyin-pro';

function toPinyin(text: string): { full: string; initials: string } {
  const syllables = pinyin(text, { toneType: 'none', type: 'array' });
  const full = syllables.join(' ');
  const initials = syllables.map((s) => s[0] ?? '').join('');
  return { full, initials };
}
```

- 多音字使用库默认词典；
- 非中文（英文、数字、标点）保留原字符；
- 结果做 `normalizeText` 归一化。

## 4. 评分

| 字段 | 基础分 |
| --- | --- |
| name | 80 |
| place | 60 |
| category | 40 |
| entities | 30 |
| summary | 25 |
| date | 20 |
| description | 15 |
| pinyin | 18 |
| initials | 10 |

- 完全相等额外 +20；
- 原文匹配优先于拼音；
- 全拼优先于首字母；
- 同一事件多字段命中时取最高分。

## 5. 片段

- 原文命中：沿用现有 `makeSnippet`，可高亮；
- 拼音/首字母命中：返回原文 `name` 或 `summary` 的前 60 字，不高亮；
- 这样避免在中文文本中强行插入拼音高亮。

## 6. 兼容性

- `SearchEntry` 增加字段，属于 shared 内部类型，不影响数据契约；
- 搜索 API 签名不变；
- Web / 移动端无需改调用方式；
- `pinyin-pro` 为纯 JS，Hermes 可用。

## 7. 测试

- `zunyi` 命中遵义会议；
- `zy` 命中遵义会议；
- `zunyi huiyi` 命中遵义会议；
- 原文「遵义」排序高于 `zunyi`；
- 英文 `Zunyi` / `Key meeting` 仍命中；
- 空查询仍返回空。
