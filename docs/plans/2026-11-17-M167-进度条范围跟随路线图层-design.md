## 1. 需求

郑和专题拆成 7 个航次图层后，用户指出：

> 进度起止日期应该等于用户筛选的路线图层的最小和最大日期

即：时间轴（进度条）的起点与终点不应固定为专题 `timeRange`，而应取当前选中路线图层中最早开始日期与最晚结束日期。

## 2. 设计

### 2.1 范围计算

新增共享函数 `routeDateRange(routes, isIncluded)`：

- 遍历传入路线，只统计 `isIncluded(entityId)` 为真的路线；
- 返回 `{ start: 最早 startDate, end: 最晚 endDate }`；
- 没有可用路线时返回 `null`，调用方回退到 `manifest.timeRange`。

统计时排除：

- 未选中的实体（`activeEntityIds` 不含）；
- 不进入图例的背景实体（`extensions.legend === false`，如郑和专题的明朝海防线）。

因此郑和专题只选第四次时，范围为 `1413-12-01` → `1415-08-12`；只选第七次时为 `1431-01-01` → `1433-07-22`。

### 2.2 时间轴与播放

Web 与移动端的 store 在以下动作后重新计算 `timeline`：

- `loadAtlas`（初始全选）
- `setActiveEntities`
- `toggleEntity`
- `soloEntity` / 取消独显（Web）
- `showAllEntities`（Web）

同时把 `currentTime` 夹到新的 `[timeline.start, timeline.end]`，避免当前时间落在范围外。

时间轴组件本身继续读取 store 的 `timeline`，因此：

- 进度条左右两端的日期自动变化；
- 刻度、事件标记、播放范围、日期输入框的 `min` / `max` 同步变化；
- 移动端时间轴同样生效。

### 2.3 回退规则

- 所有路线图层都被隐藏时，回退到专题 `manifest.timeRange`；
- 没有路线的专题仍使用原 `timeRange`；
- 事件类别/日期筛选不改变进度条范围，只有路线图层筛选会改变。

- 独显第七次时为 `1431-01-01` → `1433-07-22`；
- 当前时间自动夹到新范围；
- 播放、刻度、事件标记、日期输入都跟随新范围；
- `pnpm typecheck`、`pnpm lint`、`pnpm test` 通过。
