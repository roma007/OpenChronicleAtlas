## 1. 问题

湘江战役不是一个点，而是「四个渡口 + 三个阻击战」构成的渡江走廊。当前数据只有一个县域点：

| 项目 | 原数据 | 实际位置 | 偏差 |
| --- | --- | --- | --- |
| 湘江战役 | 111.07, 25.93（全州县城） | 界首渡口约 110.767, 25.724 | 约 25 km |
| 中央红军路线 | 宜章 → 全州县城 → 通道 | 宜章 → 道县/文市 → 界首 → 越城岭 → 通道 | 终点与走向不符 |
| 渡口 | 无 | 屏山、大坪、凤凰嘴、界首 | 缺失 |
| 阻击战 | 无 | 新圩、脚山铺、光华铺 | 缺失 |

因此地图上只能看到「红军到过全州」，看不到「从哪里过江、在哪里阻击」。

## 5. 技术取舍

| 选项 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 只改湘江战役坐标 | 改动最小 | 仍看不到渡口和阻击战 | 不采用 |
| 为 4 个渡口、3 个阻击战各建事件 | 可检索、可点击、可标注精度 | 同一区域事件增多 | 采用 |
| 把渡口只写进路线顶点 | 线条更细 | 无名称、无来源、不可检索 | 不采用 |
| 新增「湘江渡口群」防线 | 地图上能看出渡江走廊 | 多一条线，需要命名区分 | 采用 |
| 把各军团渡口写成唯一结论 | 看起来精确 | 史料互相矛盾 | 不采用 |

## 6. 兼容性、性能与安全

- 兼容性：事件与路线字段均为现有契约；`extensions` 新键旧客户端忽略；
- 性能：long-march 事件 98 → 101、路线 85 → 87，规模可忽略；
- 安全与隐私：无新增外部请求、无定位权限变化。

## 7. 测试策略

- `pnpm validate:data`：schema、ID、日期、引用完整性；
- `pnpm check:routes`：10 个新事件与活动路线距离 ≤ 30 km；
- `pnpm build:search-index`：新增事件进入索引；
- `pnpm build:mobile-data --check`：移动端内置映射最新；
- `pnpm typecheck` / `pnpm lint` / `pnpm test`。
