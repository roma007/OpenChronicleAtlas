## 2. 目标与边界

**目标**：七雄各有一条从立国到灭亡的连续主线；每个空档不超过约 40 年；部族至少与其主要互动事件相连。

**不做**：
- 春秋（前 770—前 476）单独成线；
- 前 221 之后的秦朝、百越、蒙恬北逐匈奴；
- 中山作为独立实体（Cliopatria 有前 366—前 292 切片，是否纳入另行决定）；
- 无史料锚点的会战不画精确路线，宁可不加。

## 3. 候选事件（按主体，含路线需求）

优先级：P1 必做，P2 视密度与史料再定。

## 6. 每批次的固定流程

```bash
pnpm validate:data
pnpm check:routes --atlas warring-states
pnpm check:heads --atlas warring-states
pnpm build:search-index
pnpm build:mobile-data
pnpm typecheck && pnpm lint && pnpm test
```

- 每批在 `docs/research/warring-states-events.md` 追加核对表（事件 → 日期 → 出处 → 主体 → 存疑点）；
- 每批更新 CHANGELOG 与本计划状态；
- 全部完成后三端人工验收，再由用户确认提交与 `pnpm release`。

## 7. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 时间轴事件密度翻倍，前 300—前 221 拥挤 | 中 | 依赖现有聚合；必要时同年事件合并展示，不删事件 |
| 多国联军路线端点互相打架 | 高 | 统一共用锚点（函谷关、垂沙、蕲），联军段一律按国别分线 |
| 地望存疑（李帛、垂沙、番吾） | 高 | 正文标「地望待考」；不能定位则不画线，改 `routeEvent: false` |
| 部族实体挂事件触发 `check:routes` 报错 | 中 | 每族补一段 `defense`，不调阈值、不加豁免 |
| 早期事件（前 5 世纪）史料单薄 | 中 | 只收《史记》世家有明确系年者；异说写正文，不硬凑 |
| 与既有事件主体冲突（如灭赵同时记秦、赵） | 高 | 同一战役按双方分事件，沿用现有做法，不合并主体 |
