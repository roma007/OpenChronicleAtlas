# M210 技术方案：地区标注、定位与事件地区路径

- **任务名**：地区标注、定位与事件详情地区路径
- **日期**：2026-11-20
- **里程碑**：M210
- **关联 plan**：[M210 plan](2026-11-20-M210-地区标注与定位-plan.md)
- **关联**：[M209 design](2026-11-20-M209-抗战按地区浏览-design.md)
- **状态**：已完成

## 1. 背景

M209 已支持按省/县市/地点筛选，但地图上只有省界，没有县/地点名称；用户也无法从筛选面板快速定位到选区。事件详情只显示自由文本地名，没有省/县路径。

## 2. 方案

### 2.1 县/地点标注

- `regions.json` 为县/地点补 `point`；
- Web 用 `AMap.Text` 渲染，移动端用 `Marker` + 自定义 View；
- 按缩放级别显示：
  - 院辖市：4.5 级；
  - 县：7 级；
  - 地点：9 级；
  - 选中地区始终显示；
- Web 做屏幕空间避让；移动端最多显示 80 个，优先选中地区与上级地区。

### 2.2 标注类型

| 前缀 | 含义 | 样式 |
| --- | --- | --- |
| `◎` | 县治 | 实线、深色、较实底色 |
| `·` | 地点 | 苔绿、小字号 |
| `≈` | 事件平均点（示意） | 赭色、虚线 |

县名使用完整名称，避免“锦”这类单字歧义。

### 2.3 县治点位

- `county-seats.json` 记录来源与坐标；
- 构建时优先应用，避免 `build-region-data.py` 重建时丢失；
- 来源：GeoNames CC BY 4.0、县治同名地点、事件点即县治、手工校订。

### 2.4 定位

- 新增 `regionFocus` 请求；
- 按选区内的省界、事件、路线、子地区点位计算范围；
- 单点放大到 9 级，多点 `setBounds` / `fitToCoordinates`。

### 2.5 事件地区路径

- 事件详情读取 `location.regionIds`；
- 用 `regionPath` 生成“河北省 · 清苑县 · 保定”；
- Web 与移动端同步。

## 3. 取舍

| 选项 | 结论 | 原因 |
| --- | --- | --- |
| 用事件平均点直接当县治 | 不采纳 | 会被关口/战场拉偏 |
| 全部手写 188 个县治 | 不采纳 | 工作量大、易错 |
| GeoNames + 同名地点 + 人工兜底 | **采纳** | 可复现、覆盖率高 |
| 县界多边形 | 不采纳 | 无可靠可再分发数据 |
| 标注全部常显 | 不采纳 | 低缩放过密 |
| 按缩放分级 + 避让 | **采纳** | 可读性与性能平衡 |

## 4. 验收

- 缩放 7 级河北可见县名，9 级可见地点名；
- 选中地区始终显示，可关闭“地区标注”；
- “定位”能缩放到选区；
- 事件详情显示地区路径；
- 县治/地点/近似点样式可区分；
- `pnpm typecheck`、`lint`、`test`、`build` 通过。
