## 1. 背景

项目已有 Web（`apps/web`）与移动端（`apps/mobile`，Expo/React Native，覆盖 iOS、iPadOS、Android），但没有 macOS / Windows 桌面端，也没有可执行的商店提交流水线。用户目标是把应用发布到 App Store Connect、Microsoft Store 与华为 AppGallery。

## 2. 目标

1. 新增 `apps/desktop`，用 Tauri 2 复用 Web 构建产物，一套代码产出 macOS 与 Windows 安装包；
2. 补齐 iOS/iPadOS 与 Android 的发布配置（iPad 横屏/分屏、版本号、AAB 构建入口）；
3. 提供 Apple、华为、微软三条商店提交路径的操作文档与检查清单；
4. 不改变现有 Web 部署与数据契约。

## 3. 范围

- 新增 `apps/desktop`（Tauri 2、Rust、复用 `apps/web/dist`）；
- 调整 `apps/web/vite.config.ts`：`desktop` 模式下关闭 PWA、改用 HashRouter；
- 调整 `apps/mobile/app.config.ts`：iPad 方向与分屏支持；
- 调整 `apps/mobile/src/screens/GalleryScreen.tsx`：iPad 宽度下 2–3 列图鉴；
- 新增 `apps/mobile/eas.json` 与本地发布构建脚本；
- 新增 `.github/workflows/build-installers.yml`（Web、macOS、Windows、Android；iOS 签名后出 IPA；tag 自动发布 Release）；
- 新增 `docs/guides/store-submission.md`；
- 桌面端支持独立高德 Key（`VITE_AMAP_DESKTOP_*`）并提供 Secrets 上传脚本；
- 更新 `README.md`、`docs/changelog/CHANGELOG.md`。

## 4. 非目标

- 不做 HarmonyOS NEXT（ArkTS/HAP）原生端；
- 不做 Mac App Store 的最终提审（依赖 Apple 账号与高德商用许可）；
- 不做 Windows 代码签名证书采购（依赖用户账号）；
- 不修改 `packages/shared` 与数据契约。
