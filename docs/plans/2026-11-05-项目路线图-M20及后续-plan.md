## 2. 路线图原则

1. **先发布，再扩展**：优先解决 B1–B7，避免继续堆功能却无法上架。
2. **外部依赖与内部开发分离**：需要账号/设备的任务单独列出，不阻塞可独立完成的开发。
3. **每个里程碑仍遵循 plan/design → 实施 → 验收 → 双仓 tag**。
4. **数据与平台解耦**：新增专题不改平台代码；平台能力以 shared 层为主。
5. **不为未确认的需求提前编码**。

## 3. 阶段规划

### M20：发布准备与真机验收（P0）

**目标**：把当前 v0.19.0 变成可提交商店的候选版本。

| 任务 | 产出 | 依赖 |
| --- | --- | --- |
| Android 0.19.0 APK 重建 | 签名 APK | 构建环境 |
| 真机验收 | 三专题、离线、双语、分享、时间轴 | Android 真机 |
| 商店元数据英文版 | `store-metadata-en.md` | 无 |
| 真机截图 | iOS/Android 各 4–6 张 | 真机 |
| 自定义域名方案 | 域名接入步骤与验证 | 域名 |
| 高德商用许可清单 | 合规检查表 | 用户确认 |
| 密钥重置 | 新 Web Key + Vercel 环境变量 | 高德控制台 |

**验收**：APK 可安装；核心流程真机通过；商店素材齐备；域名可访问。

### M21：体验深化（P1）

**目标**：在不改变数据契约的前提下提升性能与可用性。

| 任务 | 说明 |
| --- | --- |
| 搜索拼音 chunk 懒加载 | 首屏不再下载 pinyin-pro |
| 深色 / 高对比度主题 | Web + 移动端，地图样式同步 |
| 事件巡游模式 | 按事件逐个跳转并短暂停留 |
| 离线地图优化 | 已浏览瓦片缓存、离线提示 |
| 移动端语言/缓存持久化收尾 | 已验证项补真机回归 |
| 性能与包体 | 代码分割、首屏指标 |

**验收**：首屏 JS 降低；主题可切换；巡游可用；离线地图在已浏览区域可显示。

### M22：内容扩展（P2）

**目标**：增加第四个专题并提升史料质量。

候选专题：

- 抗日战争（1931–1945）
- 大航海时代（15–17 世纪）
- 丝绸之路全史（需评估公元前日期支持）

| 任务 | 说明 |
| --- | --- |
| 第四专题数据包 | 20–30 事件、路线、来源、封面 |
| 玄奘专题校订 | 日期、地点、来源 |
| 长征/郑和来源补全 | 页码/版本/馆藏 |
| 数据 QA 脚本产品化 | 事件-路线一致性检查 |

**验收**：第四专题可插拔接入；数据校验通过；来源可追溯。

### M23：平台化（P2）

**目标**：从「示例平台」走向「可持续内容平台」。

| 任务 | 说明 |
| --- | --- |
| 构建期搜索索引 | 专题增多后避免运行时全量加载 |
| 内容管理流程 | 专题提交模板、校验清单、发布流程 |
| schema 演进评估 | 公元前日期、事件别名、路线分段类型 |
| 多专题数据版本 | 索引级 `updatedAt` 与更新提示 |
| 可观测性 | Web 错误边界、基础埋点（可选、需隐私评估） |

**验收**：新增专题有标准流程；搜索不随专题数线性变慢；schema 变更有一致性方案。

### M24：v1.0 发布（P0/P1）

**目标**：稳定版发布。

| 任务 | 说明 |
| --- | --- |

## 6. 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 账号/设备长期不到位 | 无法上架 | 先完成可独立开发的 M21/M22 |
| 高德商用许可不明确 | 合规风险 | 提前确认，准备替代底图方案 |
| 专题增多导致搜索变慢 | 体验下降 | M23 构建期索引 |
| 史料校订周期长 | 内容准确性 | 标注初稿，持续迭代 |
| 移动端真机测试不足 | 回归风险 | M20 集中验收 |
