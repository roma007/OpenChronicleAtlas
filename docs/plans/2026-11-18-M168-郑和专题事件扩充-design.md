# M168 郑和专题七次下西洋事件扩充 — 数据方案

- **任务名**：郑和专题七次下西洋线路事件扩充
- **日期**：2026-11-18
- **里程碑**：M168
- **关联 plan**：[M168 实施计划](2026-11-18-M168-郑和专题事件扩充-plan.md)

## 1. 背景与问题

M166 把宝船队航线拆成七个航次后，航线结构清楚了，但事件密度没有跟上：

- 第一、四次各 13 / 15 个事件，其余五次只有 3—4 个，第二次只剩「起航 / 锡兰山之战 / 返航」；
- 第三、六、七次的航线只画到满剌加、榜葛剌、阿丹，与史料中「到锡兰、古里、忽鲁谟斯、东非」的记载脱节；
- 时间轴上独显某一次航次时，事件稀疏到看不出这一趟经历了什么。

M168 要解决的是「航线有骨架、事件没血肉」。

## 2. 总体思路

1. **航线补港**：按史料把每个航次实际停靠的港口补进航线顶点（仍是示意折线，不做真实航迹）；
2. **事件贴港**：新增事件一律布在航线顶点上，保证 `check:routes` 的 30km 距离约束天然成立；
3. **时间分层**：同一港口在不同航次各记一次，标题体现该次的具体动作（册封 / 开市 / 封王 / 之战 / 献俘），不写重复的「抵达某地」；
4. **争议留白**：二、三次下西洋的锡兰山事件归属、各事件具体日份，均在正文与来源备注中写明「研究推定」，不下断言。

## 3. 数据结构

沿用既有 `AtlasEvent`，不新增字段：

```jsonc
{
  "id": "ceylon-offering-1409-02",     // 小写 + 连字符
  "atlasId": "zheng-he",
  "name": { "zh": "布施锡兰山佛寺", "en": "Offering at the Ceylon temple" },
  "date": "1409-02-15",
  "location": {
    "lng": 79.86,
    "lat": 6.93,
    "place": { "zh": "锡兰山", "en": "Ceylon" }
  },
  "entityIds": ["voyage-2"],           // 只挂一个航次，避免图例重复统计
  "category": "外交",                   // 航行 / 外交 / 战斗 / 政策
  "summary": { "zh": "…", "en": "…" },
  "description": { "zh": "…", "en": "…" },
  "images": [],
  "sources": [ { "title": "《明史·郑和传》", "author": "张廷玉等", "year": 1739,
                 "note": "日期按史料纪年换算，具体日份为研究推定" } ],
  "relatedIds": [],
  "extensions": { "routeEvent": false } // 仅非航线事件
}
```

### 3.1 分类口径

| 类别 | 用在什么地方 |
| --- | --- |
| 航行 | 起航、候风、返航、远洋航段 |
| 外交 | 册封、开市、布施、调解、朝贡 |
| 战斗 | 旧港擒陈祖义、锡兰山之战、苏门答剌平苏干剌 |
| 政策 | 停罢下西洋、敕谕暹罗、献俘与贡麒麟等朝廷动作 |

### 3.2 非航线事件

南京献俘、北京贡麒麟、仁宗停罢等事件不在航线上，统一加：

```json
"extensions": { "routeEvent": false }
```

`checkDatasetRoutes` 会跳过这些事件，但搜索、详情面板、时间轴仍会显示。

## 6. 兼容性与影响

- **schema**：不变；
- **时间轴**：`timeRange` 不变，进度条范围仍取选中航次的最小/最大日期（M167 逻辑）；
- **搜索**：事件数增加，`search-index.json` 体积增大，需重建；
- **移动端**：事件数据随 `atlasData.ts` 一起打包，需重建；
- **性能**：单专题事件数从 41 增至约 100，仍在既有数据量级内（长征专题 249 个）。
