## 1. 背景

现有 12 个专题（长征、郑和、玄奘、抗日战争、徐霞客、京杭大运河、三国、宋元、隋唐、明清、西路军、以及各专题补充线），时间跨度覆盖 **190—1945**，先秦完全空白。

战国（前 475—前 221）是中国从封建分封走向中央集权的关键转型期，也是「变法—兼并—统一」这条主线的起点，与已有的三国、隋唐、明清形成完整帝制序列的前段。M77/M78 的发布说明中已把「春秋战国」列为后续计划。

## 2. 关键前置：当前日期体系不支持公元前

这不是业务问题，是工程阻塞，必须先行解决。

| 证据 | 位置 |
| --- | --- |
| 日期正则只接受 4 位正年份 | `packages/shared/src/time/date.ts` 的 `DATE_RE = /^(\d{4})-(\d{2})-(\d{2})$/` |
| 用 `Date.UTC(year, …)` 构造，年份 0—99 会被当成 1900—1999 | 同上 |
| 分享链接用同一套正则 | `packages/shared/src/share/state.ts` 的 `DATE_RE` |
| 全库最早年份为 190 | `data/atlases/index.json` |

**结论**：不做 BCE 支持，就只能把「前 475 年」写成「0475-01-01」之类的伪造日期，时间轴会显示「475 年」，违反 AGENTS.md 第 11 条「不得为了让时间轴好看而改日期」。因此 **M299 必须独立成阶段**。

## 3. 目标

1. **M299**：`DateString` 支持公元前，三端（Web / Mobile / Desktop）正确显示「前 475 年」，数据契约升到 `1.2.0`；
2. **M300**：新增 `warring-states` 专题骨架、七雄实体、分时段疆域面、封面、索引；
3. **M301**：录入主线事件（约 40—60 条）与进军/退却路线，`check:heads` 归零；
4. **M302**：七国战史线、人物层、水利与制度节点扩充；
5. **M303**：全量 QA、三端验收、发布与双仓 tag。

## 4. 范围

### 4.1 包含

- `packages/shared/src/time/date.ts`、`share/state.ts`、数据 schema 校验（M299）
- `data/atlases/warring-states/**`（manifest / events / routes / territories / assets）
- `data/atlases/index.json`、`data/atlases/search-index.json`
- `apps/mobile/src/generated/atlasData.ts`
- `docs/research/` 史料核对表、`docs/decisions/` 日期体系 ADR、CHANGELOG

### 4.2 不包含

- 春秋（前 770—前 476）：作为后续独立专题，本期只在战国开篇事件里做背景交代
- 秦朝（前 221 之后）：归入以后的「秦汉」专题
- 货币、兵器等实物专题可视化：本期只做文字事件，不新增渲染类型
- 非中国区域势力（匈奴等）：只在与七雄互动时以事件形式出现，不建独立实体层
