## 1. 目标（Goal）

搭好可运行、可校验、可扩展的 monorepo 骨架，并用「长征」示例专题在 Web 端验证
**「数据包 → shared 加载与校验 → MapLibre 渲染路线与节点」** 这条主链路，为 M2 时间轴打好地基。

## 2. 范围（Scope）

### 2.1 包含

1. 仓库初始化、`.gitignore`、双远程配置与首次双推（含 tag 前的提交策略）。
2. pnpm workspace monorepo：`apps/web`、`apps/mobile`（空壳）、`packages/shared`。
3. 共享 TypeScript 配置、ESLint + Prettier、基础 npm scripts。
4. `packages/shared`：
   - 数据契约类型与 zod schema（v1.0.0）；
   - `loadAtlas()` 数据加载器（HTTP 数据源 + 注入 fetch）；
   - 跨文件一致性校验与错误分级；
   - 时间解析/格式化等基础纯函数（不含时间轴 UI）。
5. 「长征」示例数据包：6 段路线 + 24 个事件 + 6 个实体 + 史料来源，通过 schema 校验。
6. Web 端：
   - 首页专题卡片墙（读取 atlas 索引）；
   - 专题地图页：MapLibre 底图、路线分色渲染、事件 Marker、点击只读详情面板；
   - 响应式布局骨架（桌面侧栏 / 移动抽屉占位）。
7. 移动端空壳：Expo 工程可启动、可 `expo prebuild`，占位首页；不含地图与时间轴。
8. 数据校验脚本 `pnpm validate:data` 与 CI 友好的退出码。
9. 文档：M1 发布说明、CHANGELOG、对话档案回填、tag `v0.1.0-m1` 双推。

### 2.2 不包含（Out of Scope）

- 时间轴拖动/播放/刻度自适应（M2）。
- 路线生长动画与时间驱动显隐（M2）。
- 搜索、筛选、分享链接（M3）。
- 移动端地图、时间轴、详情（M4）。
- 账号体系、后端服务、数据库（本项目初期为纯静态）。
- 第二个专题（M5）。
- 正式应用图标、隐私政策页、商店素材（M5）。
- 史料最终校订（M1 仅交付标注来源的初稿，校订为持续任务）。

## 5. 实施步骤

1. **确认方案**（本轮结束点）：用户确认 plan/design/ADR 与 Q1–Q5。
2. **T1 仓库**：`git init -b main` → 配置双 pushurl → 提交现有文档并推送。
3. **T2 脚手架**：创建 workspace 与共享配置，`pnpm install` 通过。
4. **T4→T6 shared**：先类型与 schema，再 loader，再时间函数；每步补单测。
5. **T7→T8 数据**：按契约写长征数据包；`pnpm validate:data` 零 error。
6. **T9→T11 Web**：先跑通「读索引 → 读 manifest → 渲染路线」，再补 Marker 与详情。
7. **T12 移动端空壳**：`create-expo-app` 后清理示例，验证 `expo prebuild --no-install` 生成 android/ios。
8. **T13 联调**：`pnpm -r typecheck`、`lint`、`build`、`validate:data` 全绿。
9. **T14 归档**：更新 CHANGELOG 与 release 文档 → 提交 → 双推 → 双仓 tag `v0.1.0-m1`。

## 6. 风险与应对

| 风险 | 影响 | 概率 | 应对 |
| --- | --- | --- | --- |
| 仓库未创建 / SSH 无权限 | 无法双推，违反留档要求 | 中 | 先本地提交；用户补权限后立即双推并回填对话档案；期间在对话中明确标注「未同步」 |
| 国内网络访问 OSM / MapLibre demo style 慢 | 地图空白或加载久 | 高 | style 可配置；提供本地最小 style 兜底（纯色底 + 简化边界）；文档写明切换天地图方法 |
| 长征史料日期/地点存在争议 | 数据可信度受损 | 高 | 每条事件标 `sources`；manifest 标注「初稿」；建立校订清单；不追求一次性完美 |
| 24 条事件 + 6 段路线数据量大、坐标手工整理易错 | 校验失败或路线穿越异常 | 中 | 用 schema + 拓扑自检（连续段端点距离阈值 warning）；分段小步提交 |
| Expo prebuild 依赖 Xcode/CocoaPods | T12 阻塞 | 中 | M1 验收降级为「配置与脚本就绪 + Web 验证」；M4 前在具备环境处完成真机验证 |
| monorepo 下 Metro 无法解析 workspace 包 | 移动端启动失败 | 中 | 按 design 配置 `metro.config.js` 的 `watchFolders` 与 `nodeModulesPaths`；M4 集中处理 |
| 范围蔓延（顺手做时间轴） | M1 延期、违反计划 | 中 | 严格按 §2.2 排除；新需求先写文档再排期 |
| 地图底图版权/配额 | 上线风险 | 低 | 默认 OSM 并遵守使用政策；生产环境切换有配额保障的瓦片源 |

## 7. 验收标准（DoD）

- [ ] `pnpm install` 在干净环境成功，`pnpm -r typecheck` 零错误。
- [ ] `pnpm lint` 零 error（warning 允许但需记录）。
- [ ] `pnpm validate:data` 对 `long-march` 输出 0 error；故意破坏一个字段能报出 JSON Path。
- [ ] Web `pnpm dev` 可打开首页，展示 ≥ 1 张专题卡片（长征）。
- [ ] 进入专题页可见：底图、6 段分色路线、24 个事件 Marker、默认视野正确。
- [ ] 点击 Marker 弹出只读详情：名称、日期、地点、所属主体、类型、摘要、来源。
- [ ] 桌面 1440px 与移动 390px 宽度下布局不溢出、可操作。
- [ ] 页面刷新后数据来自 `data/atlases`，代码中无任何专题硬编码文案/坐标（除示例索引）。
- [ ] 移动端空壳可 `pnpm --filter @atlas/mobile start` 启动；`expo prebuild` 配置就绪。
- [ ] 文档：对话档案、plan/design、CHANGELOG、release 说明齐全；GitHub 与 Gitee HEAD 一致；tag `v0.1.0-m1` 双仓存在。
- [ ] 密钥、证书、大体积二进制未入库。

## 8. 回滚方案

- 代码：M1 为新增目录，回滚即 `git revert` 对应提交；不涉及线上数据迁移。
- 数据：数据包独立目录，删除 `data/atlases/long-march` 不影响平台代码（首页需处理空列表）。
- 依赖：锁定 `pnpm-lock.yaml`；如需回退，恢复 lock 文件后 `pnpm install --frozen-lockfile`。
- 发布：tag 仅在双端验收通过后创建；如误发，删除双端 tag 并重新打。
