# M160 路线动态表现增强：矢量层胜出 — 方案

- **日期**：2026-11-17
- **里程碑**：M160（地图渲染）
- **状态**：矢量增强版已实施；画布原型验证后移除
- **关联**：[M110 路线动态符号与番号避让](2026-11-14-M110-路线动态符号与番号避让-design.md)

## 1. 问题

用户提出：「目前的线路表现方式太死板了，有没有更生动的表现形式？」

现状只有一条按日期截断的折线：没有出发预告，没有推进中的线头，走完就静止；播放时所有已走过的线同样醒目，正在推进的路线反而被淹没。

## 2. 两条候选路线

| 方案 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| A. 矢量增强 | 在现有 `AMap.Polyline` 上叠加淡墨预告线、线头光点、尾迹、抵达涟漪、悬停浮签；播放时压暗已走完的线 | 与标记、聚合、疆域、番号牌天然同层；零额外命中测试；移动端开销低 | 流光只能靠虚线偏移，做不出真正的粒子/渐变 |
| B. 画布统一层 | `AMap.CustomLayer` 里用 2D Canvas 重画全部路线，做沿路径流动的高光 | 效果上限高，折线可磨圆，能画连续流光 | 需重实现虚线语义、防线齿线、命中测试、tooltip；暂停时也持续 30fps 重绘，手机耗电 |

两条都做了可运行原型（`?routes=vector` / `?routes=canvas`，dev 专属切换），录同机位对比片段后由用户拍板：**采用矢量增强版**。

## 3. 矢量版最终形态

1. **未尽之路**：整段先铺一层同色淡墨虚线（`opacity 0.2`，`[3, 8]`），已走部分用实线盖上，行进方向一眼可见。
2. **线头**：DOM 标记（`atlas-route-head`），中心圆点 + 外圈 ping 扩散，随 `bearing` 旋转；线走完后收起。
3. **尾迹**：线头后方 14km 的等弧长采样折线，加粗、半透明，形成“笔尖拖墨”。
4. **抵达涟漪**：某段走完时，在终点放一圈 `atlas-arrival`，1.5s 后移除；播放与拖动时间轴都触发，拖动时按「最多 6 圈、间隔 ≥ 90ms」限流。
5. **悬停与点击**：悬停加粗 + 浮签（路线名 / 类型 / 起止日期 / 番号），点击 `setFitView` 到该段。
6. **聚焦当前**：播放或拖动时间轴时，把已走完的线透明度压到 32%，正在推进的线自然突出；松手后恢复全彩。
7. **缩放线宽**：`≤5` 级 0.78×、`≥9` 级 1.45×，总览不糊、放大不细。
8. **事件气泡**：播放或拖动跨过事件时弹出当前节点气泡（4s），拖动时跟手更新；松手后保留到计时结束，便于看清刚拖到的节点。
9. **上一 / 下一事件**：只跳时间、定位地图并弹出气泡，不直接打开详情栏；详情由气泡里的「查看详情」进入。

## 4. 取舍与后续

- 画布原型证明了流光可行，但常态渲染代价与维护面都更大，**不作为默认实现**；将来若做专题片头，可只在播放态挂一个短生命周期的画布特效层。
- 未做：节点军标符号、镜头跟随、首次出现的 stroke-in。前两项改变信息密度和操作权，需单独评估；stroke-in 与时间轴推进语义重叠，收益有限。
- 减少动态偏好（`prefers-reduced-motion`）下关闭 ping 与涟漪动画，涟漪直接不渲染。
