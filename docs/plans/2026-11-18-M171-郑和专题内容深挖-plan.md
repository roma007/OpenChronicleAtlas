## 1. 目标

把郑和专题从「航线和停靠港齐全」推进到「看得懂这是一支什么样的船队、带回了什么、为什么停下」：
补一层次级史实（船队建制、航海技术、物产贸易、结局影响），同时补齐地图标注、地名古今对照、
事件关系与分类，使 110 条「到港 / 交易 / 册封」式事件之外，还有可读的背景层。

## 2. 现状与缺口

| 维度 | 现状 | 缺口 | 影响 |
| --- | --- | --- | --- |
| 事件构成 | 110 条，外交 77 / 航行 23 / 政策 7 / 战斗 3 | 只有「到港—交易—册封」一条线，没有船队、技术、物产、结局 | 读完仍不知道宝船多大、怎么导航、为什么停 |
| 分类粒度 | 外交占 70% | 册封 / 朝贡 / 贸易 / 外交混为一类 | 筛选几乎失效 |
| 地名对照 | 110 条中仅 8 条有 `aliases` | 满剌加/马六甲、古里/科泽科德、忽鲁谟斯/霍尔木兹等全无 | 搜「马六甲」搜不到 |
| 地图标注 | 41 段航线 0 个 `label` | 看不出哪段是起航、分䑸、归程 | 分段后反而更难读 |
| 事件关系 | 24 条缺 `relatedIds` | 详情页「相关事件」为空 | 叙事断点 |
| 时长事件 | 仅 3 条有 `endDate` | 锡兰山之战、郑和之死等应有区间 | 时间轴标记为点而非段 |
| 重要度 | 95 条缺 `importance` | 与其它专题不一致（当前未参与排序，属数据完备性） | 低 |
| 配图 | 全站 `images` 为空 | 宝船、天妃碑、麒麟无图 | 可选 |

### 2.1 一条硬约束（先说清）

`manifest.timeRange` 是 1405-07-11 → 1433-07-22。**时间轴外的事件会被 `validate:data` 记为 warning，
且无法在进度条上定位**。因此：

- 1371 郑和出生、1381 入宫、1404 赐姓郑 → 写进专题说明与「太仓起航」「郑和卒于古里」正文，不做事件；
- 1911 锡兰山碑发现、2001 梁庄王墓发掘、1621《武备志》收录航海图 → 同理，进说明；
- 只有落在 1405—1433 之内的事才做成事件。

## 5. 实施步骤

每个提交都走完整闭环（数据铁律 + 发布铁律）：

1. 改数据 → `pnpm validate:data`
2. `pnpm check:routes` / `pnpm check:heads` / `pnpm check:land`（必须 0 待处理）
3. `pnpm build:search-index` → `pnpm build:mobile-data`
4. `pnpm typecheck` / `pnpm lint` / `pnpm test`
5. 本地 dev 逐航次核对（图例段数、标注、筛选、详情页相关事件）
6. `pnpm ops:inbox` → 提交 → 打 tag → 双仓推送 → `pnpm release`
7. 线上核对 `index.json` 与 `search-index.json` 的 `dataVersion` 一致

## 6. 风险与应对

| 风险 | 影响 | 概率 | 应对 |
| --- | --- | --- | --- |
| 抽象事件没有确定坐标，被 `check:routes` 判 30km 超限 | 提交被挡 | 高 | 一律标 `extensions.routeEvent = false`；确需挂航线的，坐标取航线上的水域点 |
| 事件数 110 → 140，时间轴标记过密 | 可读性下降 | 中 | 依赖现有聚类；Phase 1 先补 `importance` 便于后续做抽稀 |
| 新分类没有英文标签 | EN 界面显示中文 | 高 | 同步更新 `CATEGORY_LABELS` 并加测试断言 |
| 新增 `detachment` 类型遗漏某处 switch | 样式或校验缺失 | 中 | 类型是联合类型，`tsc` 会报未覆盖分支；补 schema 枚举与单测 |
| 分类重标 110 条与既有截图/文档不一致 | 文档过期 | 中 | 同一次提交更新 CHANGELOG 与专题说明 |
| 史料争议（宝船尺度、最远航程、卒地） | 误导读者 | 中 | 正文并列「一说」，来源标注，不写成定论 |
