## 1. 背景

原始需求 §6.6 要求「中文为主，预留 i18n（英文），数据字段支持多语言对象」。当前 shared 已有 `LocalizedString` 与 `resolveLocalized`，但：

- UI 文案全部硬编码中文；
- 事件数据没有英文；
- 日期、分类、隐私政策未按语言切换；
- 搜索索引虽合并多语言，但分类字段只有中文。

## 2. 目标

1. Web / 移动端支持中 / 英切换；
2. 所有主要界面文案双语化；
3. 两个专题的 manifest、实体、事件补齐英文；
4. 日期、分类、隐私政策按语言显示；
5. 英文检索可用；
6. 语言缺失时回退中文，不出现空白。

## 3. 范围

### 3.1 包含

- shared i18n：Locale、文案字典、分类映射、测试；
- 数据：54 个事件的英文名称/摘要/描述/地点；郑和专题 manifest 与实体英文；
- Web：语言切换、页面文案、详情、筛选、时间轴、隐私页；
- 移动端：语言切换、页面文案、详情、筛选、时间轴、隐私同意页；
- 版本 `0.7.0`、CHANGELOG、发布说明、tag。

### 3.2 不包含

- APK / IPA 打包；
- 离线缓存；
- 新增专题；
- 第三方翻译平台接入。

## 4. 实施步骤

| 步骤 | 内容 | 产出 |
| --- | --- | --- |
| S1 | 对话、plan/design 留档 | docs |

| S3 | 数据英文字段 | `data/atlases/*` |
| S4 | Web 语言状态与文案替换 | `apps/web` |
| S5 | 移动端语言状态与文案替换 | `apps/mobile` |
| S6 | 测试、构建、部署 | 验收 |
| S7 | CHANGELOG、发布说明、双仓 tag | `v0.7.0-m7` |

## 5. 风险

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 英文历史译名不统一 | 展示不一致 | 采用常见英文通名，专名保留拼音/惯用译名 |
| 文案遗漏 | 中英混排 | 用字典集中管理，逐页检查 |
| 英文文本过长 | 布局溢出 | 使用现有 truncate / 换行，移动端保持单行省略 |
| 数据翻译量大 | 进度慢 | 先覆盖名称/摘要/地点，再补描述；缺失回退中文 |
| 移动端语言不持久化 | 重启恢复中文 | 本轮先会话内切换，后续加持久化 |

## 6. 验收标准

- 中 / 英切换在 Web 与移动端可用；
- 54 个事件均有 `en` 名称、摘要、描述、地点；
- 英文搜索可命中名称、摘要、地点、类型；
- 英文日期格式正确；
- `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm validate:data`、Web 构建通过；
- 双仓 `main` 与 tag `v0.7.0-m7` 一致。
