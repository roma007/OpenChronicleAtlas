## 1. 背景

专题数据是静态文件，部署新数据后，长时间打开的 Web 标签页与移动端缓存仍可能使用旧数据。当前只有 PWA 应用壳更新提示，没有数据版本检测。

## 2. 目标

1. 构建期生成稳定的 `dataVersion`；
2. 写入 `index.json` 与 `search-index.json`；
3. Web 定时与回到前台检查更新；
4. 移动端首页检查更新并支持清缓存重载；
5. 共享版本判断函数与单测。

## 3. 范围

- `scripts/build-search-index.ts`；
- `data/atlases/index.json`、`data/atlases/search-index.json`；
- `packages/shared/src/types.ts`；
- `packages/shared/src/data/version.ts`（新建）；
- `packages/shared/src/index.ts`；
- Web store / `DataUpdatePrompt` / `App.tsx`；
- 移动端 store / GalleryScreen；
- i18n、测试、文档、版本、tag。

## 4. 实施步骤

| 步骤 | 内容 | 产出 |
| --- | --- | --- |
| S1 | 对话、plan/design 留档 | docs |
| S2 | 构建期 dataVersion | 两个 JSON |
| S3 | 共享类型与判断 | shared |
| S4 | Web / 移动端提示 | UI |
| S5 | 测试、版本、部署、tag | `v0.36.0-m36` |

## 5. 风险

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 哈希包含非数据字段 | 误报 | 只哈希 manifest/events/routes |
| 移动端缓存未清 | 仍显示旧数据 | 更新时调用 `clearAtlasCache` |
| 频繁请求 index.json | 网络开销 | 5 分钟一次 + 回到前台，文件很小 |

## 6. 验收

- 两个 JSON 含 `dataVersion`；
- 数据变更后版本变化；
- Web / 移动端提示可见；
- 共享测试、lint、typecheck、build 通过；
- 双仓 tag 一致。
