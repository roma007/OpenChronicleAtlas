- **日期**：2026-11-13
- **里程碑**：M109（UI / 数据契约原型）
- **状态**：原型已实施并通过校验
- **关联计划**：[2026-11-13-M109-地图路线军事符号原型-plan.md](2026-11-13-M109-地图路线军事符号原型-plan.md)
- **前序批次**：[M108 长征国民党军补粤军、西北军、陕军](2026-11-13-M108-长征国民党军粤军西北军陕军-design.md)

## 1. 问题

用户指出：地图上的路线「目前是两点一线这样的表现」。

现状确实如此：

- 路线数据多为 2–5 个顶点，渲染为单条 `AMap.Polyline`；
- 所有路线共用一套「实线 / 虚线 / 点线」语言，防御线只是点状虚线；
- 路线没有番号，图例只按实体着色，读者不知道这条线是哪支部队；
- 封锁线、堵截线、追击线在视觉上没有区别。

M108 补完粤军、西北军、陕军后，这个问题更明显：新路线短、直、无标注，看起来像「两个点连一条线」。

## 2. 原型范围

本轮只做用户确认的「番号牌 + 据点端点 + 防御齿线」三件事，并顺带建立路线层级。

### 2.1 路线番号契约

在 route properties 中新增两个可选字段：

```ts
interface AtlasRouteProperties {
  // ...
  /** 地图上的番号短标识，如「粤军 第一集团军」 */
  label?: LocalizedString;
  /** 番号标识落点 [lng, lat]，缺省取路线中点 */
  labelPoint?: [number, number];
}
```

- schema 与 TypeScript 类型同步补充；
- `label` 同时是「启用军事符号」的开关：只有写了 `label` 的防御线才绘制齿线与据点；
- 未写 `label` 的路线保持原样，避免影响其他专题。

### 2.2 番号牌

- 位置：`labelPoint` 优先，否则取路线中点沿法线偏移约 7 km；
- 样式：宋体、实体颜色文字、羊皮纸底、细边框、圆角胶囊；
- 显隐：
  - 缩放 ≥ 6 才显示，避免总览时 21 个标签互相遮挡；
  - 时间进度 ≥ 45% 才显示，避免线还没画到中点就出现标签；
  - 路线未发生、实体被关闭、当前路线被隐藏时同步隐藏；
  - 切换语言时随路线重建，标签文本同步更新。

### 2.3 防御齿线与据点

只对 `segmentType === 'defense'` 且带 `label` 的路线启用：

- **底图线**：改为细实线，不再用普通点虚线；
- **齿线**：沿路线每 24 km 放一个固定屏幕尺寸的短横线，旋转到路线法线方向；
  - 用 `AMap.Marker` + CSS `transform: rotate()` 实现，而不是 Polyline；
  - 这样齿线在任意缩放下都保持约 12×2 px，不会放大成「梯子」；
  - 缩放 < 6 时隐藏齿线，退化为细实线；
  - 齿线只显示时间轴已经「画到」的部分。
- **据点**：路线首尾各放一个 9×9 px 方块标记，起点随路线出现，终点在路线走完后出现。

### 2.4 路线层级

- 国民党军路线：线宽减一档、透明度降到 0.6（防御线 0.65），避免与红军主线抢视觉；
- 防御线保留原线宽（3 px），因为要承载齿线；
- 红军路线不变；
- 防御线不再显示方向箭头（`showDir: false`），进攻/追击/撤退仍保留。

### 2.5 图例

- 当专题存在「带 label 的防御线」时：
  - 「防御 / 驻守」的线型样例改为「细线 + 三道垂直齿」；
  - 下方增加说明：「齿线与方块表示封锁阵地与据点（放大后显示）。」
- 其他专题没有带 label 的防御线，图例仍显示原有点状线，不出现说明。

## 4. 技术取舍

| 选项 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 齿线用 Polyline 按公里绘制 | 纯几何、无 DOM | 放大后齿线变长，成为「梯子」 | 不采用 |
| 齿线用 Marker + CSS 旋转 | 固定屏幕尺寸，任意缩放稳定 | 每个齿一个 DOM marker | **采用**，仅用于带 label 的防御线 |
| 所有防御线都启用齿线 | 视觉统一 | 其他专题 marker 数量激增 | 不采用 |
| 以 `label` 作为启用开关 | 可逐步迁移、零回归 | 需要先补标签 | **采用** |
| 番号牌始终显示 | 信息完整 | 总览时严重重叠 | 不采用 |
| 缩放 ≥ 6 且进度 ≥ 45% 才显示 | 分级披露 | 总览时看不到番号 | **采用** |

## 5. 兼容性、性能与安全

- 兼容性：新增字段全部可选，schema 向后兼容；未写 `label` 的路线渲染逻辑不变；
- 性能：long-march 新增 72 个齿线 marker、26 个据点 marker，量级可接受；其他专题为 0；
- 移动端：本轮未渲染番号牌与齿线，仍使用原线型；schema/类型变更不影响加载；
- 安全与隐私：无新增外部请求、无定位权限变化。

## 6. 测试策略

- `pnpm validate:data`：新增 label/labelPoint 通过 schema；
- `pnpm check:routes --atlas long-march`：0 个问题；
- `pnpm build:search-index`、`pnpm build:mobile-data --check`；
- `pnpm typecheck` / `pnpm lint` / `pnpm test`；
- 浏览器实测：
  - long-march 缩放到 8 可见番号牌、齿线、据点；
  - 图例显示齿线样例与说明；
  - 中英文切换后番号牌更新；
  - anti-japanese-war 的齿线/据点数量为 0，图例不出现说明。

## 7. 未决问题

- 路线几何仍是示意折线，尚未沿真实公路、河谷、山口补点；
- 番号牌没有碰撞避让，密集区域（全州、宜章）仍可能重叠；
- 进攻/追击线尚未加「流动箭头」或播放时的线头光点；
- 面状封锁带、地形晕渲未做；
- 移动端尚未复用这套符号。
