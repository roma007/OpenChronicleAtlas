# ADR-0006：检索与分享状态方案

- **状态**：已接受（2026-11-03 实施完成）
- **日期**：2026-11-03
- **决策者**：项目负责人 + AI 开发助手
- **关联**：
  - [M3 计划](../plans/2026-11-03-M3-检索筛选与分享-plan.md)
  - [M3 方案](../plans/2026-11-03-M3-检索筛选与分享-design.md)

## 背景（Context）

M3 需要「跨专题搜索、专题内筛选、分享时间点与视野」。
项目初期是纯静态部署（Vercel/Cloudflare Pages + 静态 JSON），没有后端与数据库。
搜索数据量：M3 只有 1 个专题、28 个事件；M5 预计 2 个专题、50–60 个事件。
分享需要在不引入后端的前提下，把「专题 + 时间 + 事件 + 地图视野」编码进链接。

## 选项（Options）

### 搜索

| 选项 | 优点 | 缺点 |
| --- | --- | --- |
| A. 后端搜索 API | 索引可扩展、支持分词/拼音 | 需要服务端与运维，违背初期纯静态定位 |
| B. 构建期生成索引文件 | 首屏快、可 CDN 缓存 | 数据更新需重新构建；索引与数据可能不同步 |
| **C. 运行时加载专题并内存建索引** | 无后端、实现快、数据永远最新 | 专题多时首屏加载变慢；无法做复杂分词 |

### 分享

| 选项 | 优点 | 缺点 |
| --- | --- | --- |
| A. 短链服务 | 链接短、可统计 | 需要后端/第三方，增加依赖 |
| **B. URL query 编码状态** | 纯前端、可离线生成、可调试 | 链接较长；暴露时间/坐标（非敏感） |
| C. localStorage + 短 ID | 链接短 | 换设备失效，无法真正分享 |

## 决策（Decision）

1. **搜索采用 C：运行时内存索引**。
   - 进入 `/search` 时加载 `index.json` 与各专题数据，`buildSearchIndex()` 建索引并缓存；
   - 查询为归一化子串匹配 + 字段评分，不做分词/拼音；
   - 当专题数超过约 10 个或事件超过约 1000 条时，迁移到 B（构建期索引），并新增 ADR。
2. **分享采用 B：URL query**。
   - 参数：`t`（YYYY-MM-DD）、`event`（事件 id）、`view`（lng,lat,zoom）；
   - 所有参数独立校验，非法字段忽略；
   - 视野使用 GCJ-02（高德底图坐标），文档注明。
3. **Markdown 渲染使用 `react-markdown` + `rehype-sanitize`**，禁止原始 HTML。
4. **筛选在客户端完成**：类型/时间段在 shared 中过滤，实体沿用图例开关，时间轴作为额外约束。
5. **移动端复用 shared 搜索与分享编解码**，M4 接入系统分享。

## 后果（Consequences）

### 正面
- 零后端依赖，符合初期静态部署与双仓交付方式。
- 搜索索引与数据同源，不会出现「索引过期」。
- 分享链接可离线生成、可手工修改、便于调试。

### 负面 / 代价
- 搜索召回有限：中文分词、拼音、错别字无法覆盖。
- 专题多时 `/search` 需加载多个数据包，首屏变慢。
- URL 可能较长；视野坐标暴露用户当前查看区域（非敏感）。
- 分享链接中的视野是 GCJ-02，若未来换回 WGS84 底图需迁移。

### 后续行动
- M5 接入第二专题后评估搜索首屏耗时；超过 1s 则改构建期索引。
- 若需要分享统计/短链，另立 ADR 引入后端或第三方服务。
- 搜索质量不足时评估 `Intl.Segmenter` 或轻量分词库。
