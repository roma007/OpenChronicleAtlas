# ADR-0012：公元前日期支持（Schema v1.2）

- **状态**：已采纳
- **日期**：2026-11-24
- **关联**：
  - [ADR-0009 Schema v1.1 演进](ADR-0009-Schema-v1.1演进.md)（当时把公元前日期推迟到 v2.0）
  - [M300 战国专题分期实施](../plans/2026-11-24-M300-战国专题分期实施-plan.md)

## 背景

ADR-0009 第 3 条把公元前日期推迟到 v2.0，理由是「跨端改造与全量数据迁移，风险高于 v1.1 范围」。
现在要新增战国专题（前 475—前 221），这个前置条件已经挡在必经路径上：

- `DateString` 正则只接受 4 位正年份；
- `Date.UTC(year, …)` 会把 0—99 年当成 1900—1999 年；
- 分享参数、时间轴刻度、搜索排序、数据校验都直接假定公元日期；
- 全库最早年份为 190（`data/atlases/index.json`），没有任何 BCE 先例。

用「把前 475 写成 0475」的做法会让时间轴显示「475 年」，属于用假日期换好看，违反 AGENTS.md 第 11 条。

## 决策

### 1. 记法：带负号的四位年份

- `DateString` 扩展为 `^-?\d{4}-\d{2}-\d{2}$`；
- `-0475-06-01` 表示**前 475 年 6 月 1 日**；
- 采用**历史纪年**，不存在公元 0 年：`-0001-12-31` 之后直接是 `0001-01-01`；
- `0000-…` 与 `-0000-…` 一律判为非法。

### 2. 换算：与 JS Date 的天文纪年差 1

JS `Date` 使用含 0 年的天文纪年（year 0 = 前 1 年）。模块内统一在一处换算：

```
天文年 = 历史年 < 0 ? 历史年 + 1 : 历史年
历史年 = 天文年 <= 0 ? 天文年 - 1 : 天文年
```

外部只接触 `DateString`，不接触天文年。

### 3. 构造：禁止直接 `Date.UTC`

`Date.UTC(50, …)` 会得到 1950 年。所有 UTC 构造改走 `utcFromParts(year, monthIndex, day)`，
内部用 `setUTCFullYear`，同时修掉 0—99 年的历史坑（`0050-06-01` 现在能正确表示公元 50 年）。

### 4. 比较：禁止字符串比较

`'-0300' < '-0475'` 在字符串序里成立，但前 300 年晚于前 475 年。新增
`compareDateStrings(a, b)`，内部按解析后的时间戳比较；事件排序、日期范围计算、
分享参数校验全部改用它。

### 5. 展示

- 日期：中文 `前475年6月1日`，英文 `1 June 475 BCE`；
- 时间轴刻度：中文 `前475`，英文 `475 BCE`；刻度语言由 `generateTicks` 的 `locale` 选项传入；
- 刻度步长照旧按年推进，天文年 0 会被跳过，标签不会出现「0」。

### 6. 契约版本

- 新专题（战国起）声明 `schemaVersion: "1.2.0"`；
- 现有 11 个专题维持 `1.1.0`，**不做迁移**——校验器只校验格式，不锁定版本号；
- 旧客户端读到 `1.2.0` 专题时，若日期含负号会解析失败，属预期（能力新增，非兼容修补）。

## 后果

### 正面

- 战国、春秋及一切先秦专题具备数据表达基础；
- 顺带修掉公元 1—99 年被解析成 19xx 年的历史缺陷；
- 三端共用一套换算与格式化，不各自造轮子。

### 负面 / 风险

- 日期语义从「只有公元」变为「可含公元前」，所有新写的数据必须自检符号；
- Web 的 `<input type="date">` 不支持负年份，筛选面板里无法手输 BCE 日期（可用时间轴拖拽）；
- `toDateString` 不再借用 `toISOString`，需靠单测保证往返一致。

## 备选方案

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 写成 `0475-01-01` 正年份 | 未采纳 | 时间轴会显示「475 年」，与史实不符 |
| 增加仅展示用 `dateLabel`，排序仍用正年份 | 未采纳 | 排序与筛选仍错，且引入两套时间语义 |
| 天文纪年（含 0 年，`-0474` = 前 475） | 未采纳 | 数据作者与史料对照时极易错一年 |
| ISO 8601 扩展日期（`-000475-06-01`） | 未采纳 | 与现有四位年份数据不一致，解析分支更多 |
| 暂停战国专题 | 未采纳 | 用户明确要求补齐先秦序列 |

## 验收

- `parseDateString('-0475-06-01')` 与 `toDateString` 往返一致；
- `0000-01-01` 抛「不存在公元 0 年」；
- `0050-06-01` 解析为公元 50 年而非 1950 年；
- 跨公元前后刻度不出现 `0` 与 `19xx`；
- 现有 11 个专题 `pnpm validate:data` 全部通过；
- `pnpm typecheck && pnpm lint && pnpm test` 通过。
