# ADR-0008：静态部署与资源托管方案

- **决策者**：项目负责人 + AI 开发助手
- **关联**：

## 背景（Context）

项目初期为纯静态：Web 为 Vite 构建产物，数据为 `data/atlases` 下的 JSON/GeoJSON/图片，
移动端通过 HTTP 读取同一套数据。M5 需要确定 Web 部署平台、数据托管方式、环境变量与缓存策略，
同时为移动端提供稳定的 HTTPS 数据地址。

## 选项（Options）

### Web 托管

| 选项 | 优点 | 缺点 |
| --- | --- | --- |
| **A. Vercel** | Vite 零配置、Preview 部署、环境变量管理好 | 国内访问速度不稳定；免费额度有限 |
| B. Cloudflare Pages | 全球 CDN、免费额度大、国内相对可访问 | 构建环境与 Vite 配置需少量调整 |
| C. 自建 Nginx/对象存储 | 完全可控、可备案 | 运维成本高，需要服务器与证书 |

### 数据托管

| 选项 | 优点 | 缺点 |
| --- | --- | --- |
| **A. 与 Web 同域 `/data/atlases`** | 无 CORS、路径一致、构建即部署 | 数据更新需重新部署（可后续拆分 CDN） |
| B. 独立 CDN / 对象存储 | 数据可独立更新、缓存灵活 | 需配置 CORS、域名、缓存失效 |
| C. 打包进 App | 离线可用 | 违背「禁止各端副本」；包体大 |

## 决策（Decision）

1. **Web 托管以 Vercel 为主**，Cloudflare Pages 作为备选；两者都使用同一构建命令与输出目录。
2. **数据与 Web 同域**，路径固定 `/data/atlases`；构建时由 Vite 插件拷贝到 `dist/data`。
3. 移动端通过 `EXPO_PUBLIC_DATA_BASE_URL=https://<域名>/data/atlases` 读取同一套数据。
4. 环境变量：
   - Web：`VITE_AMAP_KEY`、`VITE_AMAP_SECURITY_CODE`、`VITE_AMAP_STYLE_ID`（可选）；
   - 移动端：`EXPO_PUBLIC_AMAP_*`、`EXPO_PUBLIC_DATA_BASE_URL`、`EXPO_PUBLIC_PRIVACY_URL`。
5. 缓存：`/data/*` 设置 `Cache-Control: public, max-age=3600`；HTML 不缓存。
6. 生产环境强制 HTTPS；Android 的 `usesCleartextTraffic` 仅开发使用。
7. 图标/启动图/封面等静态资源随仓库入库（体积小），大体积素材不入库。

## 后果（Consequences）

### 正面
- 零后端、部署简单、预览环境方便。
- Web 与移动端数据路径一致，减少环境差异。
- 构建产物自包含，便于迁移到其他静态托管。

### 负面 / 代价
- 国内访问 Vercel 可能较慢，需要 Cloudflare 备选或自定义域名。
- 数据更新需重新构建部署（M5 可接受；后续可拆 CDN）。
- 环境变量需在平台配置，密钥管理依赖平台。
- 未购买高德商用许可时，生产配额与授权仍需评估。

### 后续行动
- 用户提供 Vercel/Cloudflare 账号与域名后执行部署，记录 Preview/Production URL。
- 配置自定义域名与 HTTPS 证书。
- 若数据更新频繁，另立 ADR 拆分数据 CDN。
- 商店隐私政策 URL 指向部署域名 `/privacy`。
