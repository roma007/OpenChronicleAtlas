# ADR-0005：时间轴与路线生长动画方案

## 背景（Context）

M2 需要实现「拖动/播放时间轴 → 路线沿线生长、事件按时间显隐」。
底图已改用高德 JS API 2.0（ADR-0004），不再有 MapLibre 的 `line-gradient` 与矢量图层能力。
需要选择一种既能支持任意时间跳转、又能保持流畅的方案。

## 选项（Options）

| 选项 | 优点 | 缺点 |
| --- | --- | --- |
| A. 整段显示/隐藏 | 实现最简单、性能最好 | 没有「生长」效果，不满足需求 |
| **B. 时间驱动 + `Polyline.setPath` 截断** | 支持任意跳转；与高德渲染一致；实现成本低 | 每帧重设 path 有开销；折线拐点处生长略生硬 |
| C. Canvas/WebGL 自绘路线 | 完全控制动画、性能最好 | 工作量大，需要自己做投影、交互、层级，偏离 M2 目标 |
| D. 高德 `moveAlong` 轨迹动画 | 自带沿线移动效果 | 只适合固定速度播放，无法任意拖动跳转 |
| E. 多段 Polyline 逐段追加 | 生长自然、更新量小 | 需要预先切分数据；数据契约要增加分段粒度 |

## 决策（Decision）

1. 采用 **B：时间驱动 + `Polyline.setPath(partialPathAt(geometry, progress))`**。
2. 在 `packages/shared` 预计算每条路线的累计长度（haversine），按进度二分查找并插值出截断点。
3. 路线各分段独立计算进度：
   - `progress = (t - startDate) / (endDate - startDate)`，clamp 到 `[0, 1]`；
   - 段间不插值，避免跨越空白区域。
4. Web 端用 `requestAnimationFrame` 驱动播放，地图更新节流到约 30fps；`setPath` 仅在进度变化 > 0.001 时调用。
5. 事件显隐按「`event.date <= currentTime`」；当前事件取时间点之前最近的事件，持续型事件在 `endDate` 前保持高亮。
6. 事件气泡使用高德 `InfoWindow`，播放跨过事件时打开，4 秒后自动关闭；点击气泡暂停并打开详情。
7. 所有时间计算与路径插值放在 shared，移动端 M4 复用。

## 后果（Consequences）

### 正面
- 支持拖动、跳转、倍速等任意时间操作，不受固定动画限制。
- 不需要自研地图渲染，M2 可在现有高德地图上快速落地。
- 计算与渲染解耦，shared 可单测、可移植到 RN。

### 负面 / 代价
- 每帧 `setPath` 对高德渲染层有压力；数据量大时需要降级（如按段追加或降低帧率）。
- 折线在拐点处的生长是「截断 + 插值」，不是严格的沿线匀速视觉效果。
- 依赖高德 `Polyline` 的 `setPath` 行为；升级 JS API 时需回归。

### 后续行动
- M2 实现后做 28 事件 / 9 段路线的性能验收。
- 若单专题路线超过 ~50 段或出现明显卡顿，另立 ADR 评估「按段追加」或 Canvas 图层。
- M4 在 RN 端用 `expo-gaode-map` 的 Polyline 对应接口复用同一套 shared 计算。
