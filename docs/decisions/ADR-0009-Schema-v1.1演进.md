# ADR-0009：Schema v1.1 演进（事件别名、路线分段类型、公元前日期）

- **状态**：已采纳
- **日期**：2026-11-05
- **关联**：
  - [Atlas Schema v1.0.0](../schema/atlas-schema-v1.0.0.md)
  - [Atlas Schema v1.1.0](../schema/atlas-schema-v1.1.0.md)
  - [ADR-0002 数据契约与 schema 版本策略](ADR-0002-数据契约与schema版本策略.md)

## 背景

数据契约 v1.0.0 已支撑长征、郑和、玄奘、抗日战争四个专题。继续扩展时出现三类需求：

1. 同一事件有多个通行名称，搜索需要覆盖别名；
2. 路线需要表达进攻、撤退、防御、反击等语义，供图例与样式使用；
3. 未来可能接入公元前历史专题，但当前日期体系只支持公元 `YYYY-MM-DD`。

## 决策

### 1. 采纳事件别名（v1.1.0）

- 新增可选字段 `AtlasEvent.aliases?: LocalizedString[]`；
- 别名进入搜索索引的 `fields.name`，与正式名同权重；
- 搜索结果仍展示正式名；
- 旧数据无需修改。

### 2. 采纳路线分段类型（v1.1.0）

- 新增可选字段 `AtlasRouteProperties.segmentType?: RouteSegmentType`；
- 枚举：`advance`、`retreat`、`defense`、`counterattack`、`naval`、`supply`、`other`；
- 本轮只定义类型与校验，不接入 UI 样式；
- 旧数据无需修改。

### 3. 暂缓公元前日期（v2.0）

- 当前 `DateString` 固定 `YYYY-MM-DD`，解析、时间轴、格式化、分享参数均按公元日期处理；
- 可选方案包括带符号年份、ISO 8601 扩展日期、仅展示用 `dateLabel`；
- 任一方案都需要跨端改造与全量数据迁移，风险高于 v1.1 范围；
- 结论：推迟到 v2.0，届时单独评估并保留 v1.x 兼容读取。

## 后果

### 正面

- 别名提升搜索召回，不需要新增索引字段；
- 分段类型为后续图例、线型、动画方向提供语义基础；
- 所有新增字段可选，v1.0 数据与客户端保持兼容。

### 负面 / 风险

- 别名可能与正式名产生重复命中，需要在数据侧控制质量；
- 分段类型暂无 UI 消费方，短期只是契约预留；
- 公元前日期仍未解决，古代专题接入继续受限。

## 备选方案

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 把别名写入 `extensions` | 未采纳 | 缺少校验与搜索约定 |
| 用 `segmentType` 替代路线 `name` | 未采纳 | 名称仍有展示价值，类型是补充 |
| v1.1 同时实现公元前日期 | 未采纳 | 跨端改造与数据迁移风险过高 |

## 验收

- `aliases` 与 `segmentType` 通过 zod 校验；
- 别名可被搜索命中；
- manifest 与 `index.json` 升为 `1.1.0`；
- 现有四专题数据校验、测试与构建通过。
